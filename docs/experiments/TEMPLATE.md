# <실험 제목> — <장비 라벨>

> **이 서식은 2026-08-18 두 ATOM 보고서를 대조해 만들었다.** 아래 필드는 장식이 아니라
> **그때 없어서 판정이 막혔던 항목**이다. 두 보고서가 같은 프로필에서 서로 다른 Finding
> 수를 보고했는데, 실제 서빙 모델과 revision이 어느 쪽에도 없어서 "모순인가 아닌가"를
> 사흘 동안 가르지 못했다. 필드가 왜 있는지 모르면 다음 사람이 뺀다 — 그래서 각 필드에
> 그 필드가 없었을 때 무엇을 못 했는지를 함께 적어 둔다.
>
> 채울 수 없는 값은 **`미기재`로 남긴다. 지어내지 않는다.** 빈칸은 그 자체로 다음 실험이
> 무엇을 챙겨야 하는지를 가리킨다.

| 항목 | 값 | 이 값이 없으면 |
| --- | --- | --- |
| 실험 종료 시각 | `YYYY-MM-DD HH:MM KST` (분 단위. UTC 병기 가능) | 두 실험 중 **어느 쪽이 먼저였는지** 정할 수 없다. "첫 완주"를 두 사람이 동시에 주장한 것이 이 필드가 생긴 계기다 |
| 실제 서빙 모델 | `hf://<repo>@<40 hex revision>` | **`--served-model-name`은 별명이라 근거가 못 된다.** 별칭을 썼다면 별칭과 실모델을 함께 적는다 — 0.6B를 `qwen3-4b`라는 이름으로 서빙한 기록이 4B의 결과로 읽혔다 |
| `repo_commit` | 40 hex (+ dirty 여부) | 같은 명령이 다른 코드에서 돈 것을 구분하지 못한다 |
| `run_id` | `run_YYYYMMDD_NNNN` | — |
| run 산출물 경로·보존 여부 | 경로 + 보존/삭제 | **`run_id`만으로는 부족하다.** `gc`가 지운 번호를 같은 날 새 run이 재사용하므로([open-questions.md](../open-questions.md) R7), 회의록에 적은 run_id가 나중에 **다른 데이터를 가리킨다** |
| `tool_runner` | 프로필 선언값 / 실제 사용값 | 오버라이드는 [evaluation.md](../evaluation.md) §2.3 규칙 2의 예외다. 덮었다면 **왜 덮었는지**를 함께 적는다 |
| `--device` | `atom` / `slurm` / … | 규칙 5("장비가 다른 run은 같은 비교 셀에 넣지 않는다")가 이 기록 위에 선다 |
| `tool_images` digest | `sha256:…` **+ 종류** | 런타임마다 적는 값의 종류가 다르다(docker=이미지 config sha256 / singularity=SIF 파일 sha256 / podman=RepoDigest). **종류 없는 digest는 비교할 수 없다** — [portability.md](../portability.md) §5 #4 |
| `--gpu-memory-utilization` | 값 **+ 그 시점의 분모(GiB)** | 비율만 적으면 재현되지 않는다. 이 장비의 분모는 물리 통합메모리 **119.7 GiB**이고 cgroup 상한과 다르다([README.md](README.md) 확정 #4) |
| 동시에 떠 있던 다른 서버 | 포트 · 모델 · util | **제한 단위가 세션이 아니라 사용자다.** 계정을 공유하므로 같은 계정의 다른 서버가 `memory.high`를 밀어올린다 — 이게 없으면 "왜 이번엔 throttle이 걸렸나"를 사후에 못 가른다 |
| 원문 산출물 보존 위치 | 경로 또는 **`보존하지 않았다`** | `bench` stdout을 놓쳐 측정 기록이 재구성본이 된 전례가 있다. **"보존하지 않았다"도 값이다** |
| 서빙 서버 stdout | 경로 또는 **`보존하지 않았다`** | 위 필드와 갈라 둔다 — **셋 다 이 값이었다.** run 산출물은 파일로 남는데 서버 로그는 포그라운드로 띄우면 창과 함께 사라진다. 그 창에만 있는 것이 `Prefix cache hit rate`이고, 장부 `cached_tokens`가 0인 이유를 가르는 유일한 대조값이다([README.md](README.md) 「서빙 서버 stdout을 파일로 받는다」) |

## 6. 반증 조건

**이 실험이 실패했다면 무엇이 틀린 것이었나.** 실험이 무엇을 배제했는지를 적는 자리다.
성공만 적으면 그 성공이 무엇을 뜻하는지 알 수 없다.

> 예: "프로브가 실패했다면 — 우리가 읽는 메트릭 이름이 이 서버 버전에 없다는 뜻이다.
> 성공했으므로 이름 매핑은 아직 필요 없고, 부재 1건은 그 경계가 어디인지를 가리킨다."
