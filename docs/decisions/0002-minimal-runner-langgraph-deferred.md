# 0002. 오케스트레이터를 순수 함수 최소 러너로 시작하고 LangGraph를 보류한다

- 상태: 제안
- 일자: 2026-08-08
- 관련: [engineering-guide.md](../engineering-guide.md) §4, [open-questions.md](../open-questions.md) D7

## 배경

D7은 "LangGraph v1 확정 여부"를 **노드를 순수 함수로 유지한다는 전제 하에** 열어 두었다.
그 전제가 결정을 뒤집는다. 노드가 `def run(ctx, ...) -> ...` 형태의 순수 함수라면,
그것을 무엇이 호출하는지는 노드 코드에 나타나지 않는다. 그러면 오케스트레이터 선택은
**나중에 해도 비용이 같은 결정**이 된다.

v1에서 실제로 필요한 제어 흐름은 순차 실행, 후보별 반복, 예산 소진 시 중단 세 가지다.
분기·병렬·체크포인트·재개는 아직 요구되지 않는다. 지금 그래프 프레임워크를 넣으면 노드
시그니처에 프레임워크 타입이 스며들고, 그 순간 D7은 "확정 여부"가 아니라 "이미 확정됨"이
된다 — 열어 두기로 한 결정을 코드가 대신 닫아 버린다.

## 결정

v1 러너는 `src/orchestrator/runner.py`의 순차 함수 하나다. 노드 시그니처에 LangGraph
타입을 **노출하지 않는다.** 노드가 아는 것은 `RunContext` 하나뿐이고, 그 안에는 4개
인터페이스와 trace·예산·정책이 들어 있다.

## 대안과 기각 사유

| 대안 | 기각 사유 |
| --- | --- |
| 지금 LangGraph 채택 | 필요한 제어 흐름이 순차 3종뿐이다. 얻는 것 없이 노드 시그니처에 프레임워크가 들어오고 D7이 코드로 닫힌다 |
| 지금 다른 그래프 프레임워크(Temporal 등) | 같은 이유. 게다가 외부 서비스 의존이 늘어 GPU 없는 팀원의 실행 환경이 무거워진다 |
| 노드를 상태 가진 클래스로 | 순수 함수 전제를 깬다. 그 전제가 무너지면 오케스트레이터 교체 비용이 실제로 커진다 |

## 결과

- 얻는 것: 의존성 0개, 노드 단위 테스트가 프레임워크 없이 돌아감, D7이 열린 채로 유지됨
- 잃는 것: 체크포인트·재개·병렬 실행을 직접 만들어야 한다. v1에는 요구가 없지만 생기면
  그때가 재검토 시점이다
- **되돌리는 비용: 낮다(그리고 그것이 이 결정의 핵심이다).** 노드가 순수 함수인 한
  러너만 교체하면 된다. 이 비용을 낮게 유지하는 것이 "노드에 프레임워크 타입 금지"의 목적이다
