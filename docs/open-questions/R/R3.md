## 왜 위험한가

코드 리뷰만으로는 보장 불가. 누락 시 모든 비교 결과 무효. **부분 착수**: `eval/leakage/`가 [evaluation.md](../../evaluation.md) §4 표의 7개 중 2개(hash 교집합, CVE·flag·문제명·patch diff 마스킹)를 구현하고 CI에서 돈다. 남은 5개(Patch Leakage 출처 검사, 중복 데이터 제거, Time Split, Prompt Logging, Reproducibility)는 미구현이므로 **해결 아님**. **2026-08-22 — Prompt Logging 행은 절반만 움직였다**: D19 구현으로 모델 입력 전체가 `{run_dir}/prompts/`에 남고 누출 스캐너의 기본 대상에도 들어갔지만, §4 표가 그 행에 요구하는 **자동 검증("로그 존재 검사")은 여전히 미구현**이다 — 프롬프트 파일이 없는 run을 무효로 판정하는 코드가 없다. **구현 수는 2 그대로다**. **2026-08-22 — 스캔 면이 실행 환경에 좌우된다는 것이 드러났다**: `RUN_GLOBS`가 `REPO_ROOT.glob("artifacts/*/…")`이라 **저장소 밖 `--artifacts-root`로 돈 run은 기본 호출에서 한 건도 안 잡힌다.** ATOM 검증에서 인자 없는 `python -m eval.leakage`가 경로 4개를 스캔했는데 그것은 그 체크아웃에 남아 있던 **옛 run들**이고, 방금 돈 `run_20260821_0007`의 프롬프트는 `--scan`으로 명시해야 들어왔다(5개). `artifacts/`는 gitignore돼 있어 커밋 오염은 없지만, **같은 명령이 장비에 남은 잔여물에 따라 다른 것을 검사한다** — "검사했다"가 무엇을 검사한 것인지 명령만 보고 알 수 없다
