> ### 2026-09-09 — 로스터 확정으로 **대상이 넷에서 둘(B안이면 셋)로 줄었다**
>
> 이 항목은 ADR 0010이 **제안**이던 때 넷으로 등재됐다. 그 ADR이 같은 날 **승인**되면서
> ([CONTEXT.md](../../../CONTEXT.md) §1이 로스터 정본이다) 넷 중 둘이 §7로 **기각**됐다 —
> `phi-4`(scout_injection · 대신 `qwen3-8b`)와 `qwen3.6-35b-a3b`(Auditor · 대신 A/B).
> **기각된 둘은 온보딩이 사라졌으므로 여기서 뺀다.** `qwen3.6-35b-a3b`는 §7이 *"2차 후보로
> 남긴다"*고 적었으나 **2차 후보는 로스터가 아니고 온보딩 대상도 아니다** — 2차 후보로
> 올라오면 그때 아래 표에 다시 넣는다.

로스터가 확정된 뒤 남은 미검증 신규 모델은 **둘**이다 — `gpt-oss-20b`(Critic)와 `qwen3-reranker-4b`(리랭커). **그리고 Auditor가 B안으로 정해지면 `nemotron-3-super-120b-a12b`가 셋째로 들어온다** — A안(`qwen3-coder-30b-a3b`)은 실측이 있는 현행 모델이라 이 리스크의 대상이 아니고, **A/B는 아직 안 정해졌다**(ADR 0010 §2 · [D24](../D/D24.md)). 세는 방식은 [09-08 조사](../../research/2026-09-08-roster.md) §8과 같다 — *"온보딩 — 신규 둘(B안이면 셋), 위험 큰 것부터"*. **2026-09-09에 `gpt-oss-20b` 하나가 처음 떴고 나머지는 아직 뜬 적이 없다.**

**그보다 한 단계 앞이다 — 셋은 registry에 아직 없다.** `config/models.yaml`의 모델 키는 일곱이고(`fake`·`qwen3-4b`·`qwen3-8b`·`qwen3-coder-30b-a3b`·`devstral-small-2-24b`·`qwen3-embedding-0.6b`·`qwen3-reranker-0.6b`), 셋 중 어느 이름도 `config/`·`src/` 어디에도 없다 — **로스터 확정 뒤 다시 grep했고 0건이며 registry 키는 그대로 일곱이다.** [CONTEXT.md](../../../CONTEXT.md) §1의 「registry 등재」 열이 그 셋에 ❌를 달아 같은 것을 적는다. 등재는 [ADR 0010](../../decisions/0010-harness-structure-and-model-roster.md) 후속 3의 **PR A**가 한다. **`checksum: 0`·`benchmark: 0`은 미실측 표시인데**(CLAUDE.md §0) **셋에는 그 0을 적을 행조차 없다** — 안 잰 것이 아니라 아직 없는 것이다.

셋 각각에 다른 관문이 있다 — **셋째 행은 Auditor B안을 고를 때만 산다.**

### 2026-09-09 — `gpt-oss-20b` 첫 관문 실측 ([2026-09-09 gpt-oss-20b 온보딩 보고서](../../experiments/harness/2026-09-09-gpt-oss-20b-onboarding-atom.md))

| 관문 | 결과 |
| --- | --- |
| sm_121 MXFP4 기동 | **통과** — MoE backend는 **MARLIN**, attention은 `TRITON_ATTN` 하나뿐 |
| 가중치+non-torch | **14.91~16.06 GiB** (3회, 같은 인자에서 7.7% 흔들린다). checkpoint 12.82 대비 **1.16~1.25배** `[계산]` |
| **structured output** | **실패** — `xgrammar`는 5/5 오답(JSON은 4/5 유효)·`guidance`는 5/5 HTTP 500. `response_format` 없이는 3/3 정답 |
| Critic 반박 정확도 | **여전히 미측정** — bench 범위 밖이다(아래) |

⚠ **`valid_ratio`만 보면 0.8이라 통과로 읽힌다. verdict는 0/5다.** 둘을 갈라 읽는다.

⚠ **이 결과는 `cli bench`가 아니라 `vllm serve` + `curl`로 냈다** — 모델이 registry에 없어 프로필에 못 올린다. 그래서 「닫히는 조건」의 `roles.*.startup.ok`·`structured_output.valid_ratio` 필드는 **아직 안 채워졌다.**

⚠ **미확인 하나** — `--structured-outputs-config.reasoning_parser`를 CLI로 명시하지 않았다(EngineCore는 `openai_gptoss`로 채웠다). 명시·`enable_in_reasoning=True`·`outlines` 셋이 미측정이고, **어느 하나에서 verdict가 움직이면 위 「실패」가 뒤집힌다**(보고서 §5·§6).

### 2026-09-11 — 셋 중 하나 + 어휘 축을 쟀다. **둘 다 부정이다** ([어휘 × 플래그 보고서](../../experiments/harness/2026-09-11-gpt-oss-structured-vocab-flag-atom.md))

**아홉 팔로 축 다섯을 갈랐고 전부 기각이다.**

| 갈린 축 | 결과 |
| --- | --- |
| `reasoning_parser` 명시 | **기각** — verdict 시퀀스가 **순서까지 동일** |
| 어휘 (`report33` / `decision` / `describe`) | **기각** — 1/5 · 1/5 · **0/5**. 서술 어휘가 제일 나쁘다 |
| **enum 순서** 뒤집기 | **기각** — 정답을 index 1로 옮겨도 `safe`(index 0)를 4/5로 고른다. **위치가 아니라 의미를 따라간다** |
| **속성 순서** (`reason` 먼저) | **기각** — JSON 유효가 5/5→3/5로 **악화**되고 verdict는 0/3 |
| **백엔드 `outlines`** | **5/5 HTTP 500 ×2팔.** 09-09의 `guidance`와 같은 자리 |

**결정적 관측 — 같은 JSON 객체 안에서 두 필드가 모순된다.**

```
1 json True | safe | The code demonstrates a clear use-after-free. After the call to `free(p)` …
4 json True | safe | Yes. After calling free(p), the pointer still holds the address of a region
                     that has been returned to the heap allocator. Writing to that address …
```

`reason`을 **앞에** 놓아 정답을 먼저 쓰게 해도 그 직후 `verdict: safe`가 나온다 — **「추론 전에 커밋한다」가 아니다.** 유효 33시행 중 **28(85%)이 「문제 없음」 쪽**이고, **자유서술은 27/27 정답**이다. **틀리는 것은 enum 토큰 하나다.**

⚠ **그래도 「`xgrammar` 구현 탓」으로 단정할 수 없다** — 다른 두 백엔드가 500이라 **대조가 없다.** 남은 미측정은 `enable_in_reasoning=True`와 **enum 제약을 뺀 `verdict`**(이 데이터가 새로 낸 항목)다.

⚠ **[ADR 0010](../../decisions/0010-harness-structure-and-model-roster.md) 「다시 열리는 조건」은 아직 발동 안 한다.** 그 줄이 (나) Critic 교체를 *"2단 추출로도 안 닫히면"*으로 걸었고, **(가) 2단 추출은 아직 안 쟀다.** 이 실측이 오히려 (가)의 근거를 준다 — 자유 텍스트는 스키마 안에서도 맞는다.

### 온보딩 관문이 하나 더 있다 — 모델 밖 에셋

`gpt-oss` 계열은 **Harmony vocab이 모델 가중치 밖의 별도 에셋**이고, 없으면 **전 요청이 500**이다. 우리 망에서 그 다운로드가 **약 77 KiB/s** `[계산]`라 라이브러리 기본 타임아웃으로는 실패한다 — 차단이 아니라 느린 것이다. `TIKTOKEN_ENCODINGS_BASE`에 로컬 디렉터리를 물려야 하고 `TIKTOKEN_RS_CACHE_DIR`로는 안 된다. **등재(PR A) 시 `config/models.yaml` 주석의 「기동 조건」에 들어가야 한다**([model-serving.md](../../model-serving.md) §3이 모델별 기동 조건을 거기 두라고 적는다). 나머지(리랭커 4B · B안이면 Nemotron)에도 같은 종류의 에셋이 있는지는 **안 봤다.**

그리고 **Critic 반박 정확도**(model-serving.md §3 체크리스트 7번)는 위 관문들과 별개다 — bench 범위 밖이고 고정 반박 표본이 필요하다. `gpt-oss-20b`는 네이티브 MXFP4라 "고정밀 대비 NVFP4"라는 R2의 틀이 맞지 않고, **표본 자체**(진짜 N + 오탐 N)에서의 정확도로 재정의된다(D4).

## 왜 위험한가

**다음 벤치마크가 이 셋 위에 선다**(A안이면 둘이다). 하나가 첫 관문에서 막히면 그 자리의 2차 후보(ADR 0010 「다시 열리는 조건」)로 갈아타야 하고, 그 판단은 다운로드·스냅샷·checksum을 다시 하는 비용을 동반한다. 온보딩 순서를 위험이 큰 것(`gpt-oss-20b`)부터로 둔 이유다.

## 닫히는 조건

대상 각각에 대해 `cli bench`의 `roles.*.startup.ok`와 `structured_output.valid_ratio`가 나오고, 리랭커는 D63 (a)의 결과가, Critic은 반박 표본의 정확도가 실험 보고서로 남으면 닫힌다. 하나씩 닫히면 이 행에 그 사실을 적고, **대상 전부가 닫히면** 상태를 바꾼다.

**대상 수를 정하는 것은 Auditor A/B다.** A안이면 둘(`gpt-oss-20b`·`qwen3-reranker-4b`)로 확정되고, B안이면 `nemotron-3-super-120b-a12b`가 셋째로 더해진다. **A/B가 미결인 동안에는 둘이 반드시이고 셋째가 조건부다** — 셋째를 미리 재 두면 B안일 때 온보딩이 앞당겨지고 A안일 때 버려진다. 어느 쪽이 싼지는 여기서 정하지 않는다.

**`gpt-oss-20b`는 아직 안 닫혔다.** 기동은 답이 나왔지만 `cli bench` 필드가 아니고, 구조화 출력은 **실패로** 답이 나왔으며(미확인 셋이 남아 있다), 반박 정확도는 미측정이다. **「닫힘」과 「부정으로 답이 나옴」은 다르다** — 구조화 출력이 끝내 안 되면 그것은 R8이 닫히는 것이 아니라 `ADR 0010`의 Critic 자리가 바뀌는 것이다.
