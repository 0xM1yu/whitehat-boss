# D52 — trigger_status를 내라고 시키는 프롬프트가 저장소에 없어 그 필드는 구조적으로 항상 null이다

## 내용

**2026-08-29 (a)로 해소. 단 기본 설정에서는 여전히 전량 `null`이고 그것은 D54다** **2026-08-29 닫힘** ([v2 스모크 보고서](../experiments/harness/2026-08-29-prompt-v2-smoke-atom.md) §3). PR #54가 `prompts/{scout,auditor,critic}/v2`를 `main`에 넣었고 `trigger_status`는 그중 `prompts/auditor/v2/`에만 있다 — 다섯 값 전부이고 저장소에 0건이던 `no_signal`도 들어왔다. **같은 서버 프로세스·같은 대상에서 `config/models.yaml` 한 줄만 갈라 대조했다**: v1 → `trigger_status":null` **×6**, v2 → `trigger_status":"triggerable"` **×6**. **음성 대조군도 있다** — 스키마만 주고 프롬프트 없이 부른 서버 직접 프로브가 그 키를 **안 냈다**(선언된 optional 4개를 다 안 냈고 required 8개는 다 냈다). ⇒ **스키마 자리는 필요조건이고 프롬프트가 충분조건이다.** ⚠ **닫히는 것은 "저장소에 프롬프트가 없다"뿐이다.** `config/models.yaml`의 어느 모델도 v2를 고르지 않으므로 **기본 설정으로 도는 모든 run은 여전히 전량 `null`이고, 그것은 결함이 아니라 미결 판단이다** — D54가 그 자리다. **팀 2×2가 도는 중에 `models.yaml`을 v2로 넘기지 않는다**: [evaluation.md](../evaluation.md) §2.3 규칙 4로 그 매트릭스가 전량 재측정이 된다. 아래는 등재 당시 기록이다. **2026-08-29 실측.** `prompts/` 어느 파일에도 `trigger_status` 문자열이 **0건**이다. 하네스는 프롬프트를 저장소에서만 읽는다 — `src/orchestrator/prompt_loader.py`의 `PROMPTS_DIR = <repo>/prompts`이고 `load_prompt()`가 `prompts/<role>/<version>/prefix.md`를 연다. **그래서 깨끗한 체크아웃으로 돈 run은 스키마가 받을 자리를 내줘도 그 값을 못 받는다.** PR #53 본문이 인용한 요구사항이 정확히 그것을 말한다 — "The prompt and harness schema must **both** contain `trigger_status` before running the smoke test". **하네스 절반은 들어왔고 프롬프트 절반이 안 들어왔다.** **열거값도 다섯 중 넷만 저장소에 있다**: `prompts/single/v2/prefix.md` 규칙 4가 `triggerable`· `guarded`·`no_reach`·`reachability_unknown`을 정의하지만 그것은 **`rca_draft` 첫 문장의 분류**이지 이 필드가 아니고, **`no_signal`은 저장소 어디에도 0건**이다(가장 가까운 것은 같은 파일 98행 표의 산문 "No weakness signal confirmed at all"). PR 본문이 인용한 `auditor_prefix.md`라는 파일도 저장소에 없다 — 영문·88~97행이라는 인용이 `single/v2/prefix.md`(226행)의 그 줄과 안 맞으므로 **서버에만 있는 다른 판본**이다. **왜 중요한가**: 이 필드의 채움률을 재면 0이 나오는데 그것이 "모델이 안 냈다"로 읽힌다. 원인은 모델이 아니라 프롬프트 부재다. 그리고 프롬프트가 저장소 밖에 있으면 `RunRecord.prompt_versions`와 `prompt_sha256`가 지키려는 재현성 기록이 성립하지 않는다 — 같은 `prompt_version`이 장비마다 다른 내용을 가리킬 수 있다. 선택지: **(a)** 서버의 확정 프롬프트를 `prompts/<role>/<version>/`에 **새 버전**으로 등재한다 — 하네스가 읽는 유일한 경로이고 `prompt_versions`가 run 기록에 남는다 **(b)** 기존 버전을 제자리 수정한다 — 같은 `prompt_version`이 두 내용을 가리키게 되므로 그 이전 run과의 비교가 깨진다 **(c)** 그대로 두고 "이 프로필에서 `trigger_status`는 측정 불가"를 조건으로 명시한다 — 필드를 낸 목적이 관측이었는데 관측이 안 된다
