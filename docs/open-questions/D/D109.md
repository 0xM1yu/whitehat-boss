# D109 — 추론 채널을 FT 레코드로 내보내는 길이 없고, 서버가 추론을 어느 키로 싣는지 실서빙에서 안 쟀다

| 상태 | 관련 문서 |
| --- | --- |
| **열림** | `src/adapters/openai_compat.py`의 `_reasoning_from()` · `src/interfaces/model_client.py`의 `AttemptRecord.reasoning`·`reasoning_field` · `src/orchestrator/context.py`의 `_record_failed_responses()` · `src/orchestrator/prompt_log.py`의 `write_reasoning` · `src/orchestrator/trace.py`의 「추론 채널」 행, [ADR 0012](../../decisions/0012-harness-canon-v2.md) 결정 7, [D84](D84.md) |

> 인덱스: [docs/open-questions.md](../../open-questions.md) · 추적 미러: 등재 머지 뒤에 연다

## 내용

**관측 [코드 · 2026-10-13 · 이 등재 PR의 트리].** [D84](D84.md)를 좁혀 닫으면서 남은 몫을 여기로 옮겼다.
아래는 run에서 나온 값이 아니라 코드를 열어 확인한 것이다.

### 이미 하는 것

- `_post()`가 `message.reasoning`·`message.reasoning_content`를 **둘 다** 읽는다(`reasoning` 우선, 문자열인
  첫 키). 키 없음·`null` → `None`, 빈 문자열 → `""`. 시도마다 `AttemptRecord.reasoning`·`reasoning_field`.
- 응답 원문과 같은 칸·같은 조건(실패·버려진 시도는 항상, 성공 최종은 `run --keep-responses ROLE` 역할만)으로
  `prompts/…_reasoning[_retryK].txt`를 쓰고 `model_call`의 `reasoning_refs`·`reasoning_sha256`·
  `reasoning_field`가 가리킨다. 읽는 법은 `src/orchestrator/trace.py`.

### 아직 못 하는 것

1. **서버가 추론을 어느 키로 싣는지 실서빙에서 안 쟀다.** 코드는 두 이름을 다 읽지만, vast 서빙
   (`--reasoning-parser qwen3`)의 응답이 `reasoning`인지 `reasoning_content`인지는 run을 돌려 `reasoning_field`를
   읽어야 안다. ATOM의 gpt-oss는 `reasoning`이었다([2026-09-12 보고서](../../experiments/harness/2026-09-12-critic-gptoss-token-accounting-atom.md) §4)
   — 서빙 모델이 달라 그것으로 대신하지 않는다. 두 키 다 안 오면(파서 없음·parser가 다른 필드명) 추론은 조용히
   `None`이다 — 그때 `reasoning_*` 키가 통째로 없다는 사실만 남으므로 **첫 run에서 키 부재를 확인한다.**
2. **내보내기(export)가 없다.** ADR 0012 결정 7은 「원문 기록 + 역할별 내보내기」를 하네스 책임으로 든다.
   기록은 위에서 생겼고, (프롬프트, 응답, 추론)을 역할별 FT 레코드로 묶는 명령과 형식은 **데이터셋팀의
   레코드 형식이 온 뒤에** 정한다 — 이 저장소가 앞서 정하지 않는다.
3. **추론이 `--keep-responses` 밖의 깨끗한 성공에서는 안 남는다.** 성공 호출의 추론을 전 역할에 남길지는
   디스크(같은 보고서가 추론 최대 16,381토큰을 적는다)와 데이터 수요로 정하는 일이라 형식과 같이 기다린다.

## 선택지

- **(가) 첫 vast run에서 `reasoning_field`를 읽고 닫는다 + 내보내기는 데이터셋팀 형식 후에 별도 이슈로.**
- **(나) 성공 최종의 추론을 기본으로 남긴다.** 디스크 대가가 있어 수요가 확인된 뒤.

## 닫히는 조건

실서빙 run 하나에서 `reasoning_field`가 서버의 실제 키 이름으로 채워진 것을 확인하고, 데이터셋팀의
FT 레코드 형식에 맞춘 역할별 내보내기가 들어오면 닫힌다.
