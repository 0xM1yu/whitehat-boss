## 내용

**⏸ 남은 부분(등가화)은 모델 선정 대기로 보류 (2026-08-30, 5차 회의).** (b) 기록은 PR #56으로 구현됐고, 모델 간 샘플링을 같게 맞추는 등가화 (a)/`--generation-config vllm`는 모델 로스터가 정해진 뒤다. **2026-08-29 (b) 구현 — 부분 해소.** `RunRecord.model_sampling: dict[역할, ModelSampling]`을 신설해, 각 실서빙 모델이 `generation_config.json`에 **선언한** 샘플링(`top_k`·`repetition_penalty`·`temperature`·`top_p`)을 역할별로 박제한다(`src/schemas/run.py`, `src/adapters/generation_config.py`가 토크나이저와 같은 HF 캐시 리졸버로 읽고, factory가 `Deps`로 날라 러너의 계층 규칙을 지킨다). D29 원문의 ②(모델마다 갈린다)가 이제 기록에 드러나 비교가 조용히 오염되지 않는다. **여전히 부분인 이유 셋**: ① 이것은 **모델 선언값**이지 서버 실효값이 아니다 — 누가 `--generation-config vllm`으로 띄우면 모델 파일값이 안 적용되는데 그 서빙 플래그는 하네스가 못 본다 ② (b)는 축을 **드러낼** 뿐 **등가화**하지 않는다 — 모델 간 샘플링을 같게 맞추려면 (a) 또는 `--generation-config vllm`이 별도로 필요하다. ③ **역할이 맵에서 빠진 이유가 한 가지가 아니다** — `declared_sampling_by_role`이 `None`인 역할을 통째로 빼는데 그 `None`은 `source` 없음(Fake) · 스냅샷 리졸브 실패 · 파일 없음 · 파일 깨짐 · 선언 키 0개 · 검증 실패를 **모두** 뜻한다. 앞 넷은 **우리 쪽 기록 구멍**이고 다섯째만 **실험 사실**인데 기록이 둘을 안 가른다. 이 필드의 목적이 "모델마다 갈리는 축을 감사 가능하게 만드는 것"이므로 읽는 사람이 "granite가 선언을 안 했다"와 "granite 스냅샷을 못 찾았다"를 갈라야 한다. run 수준에서는 `None`(옛 manifest)과 `{}`(읽었으나 없음)가 갈리지만 **역할 수준에서는 안 갈린다.** 다음 수는 읽기에 성공했으나 선언이 없는 역할에 빈 `ModelSampling()`을 남기는 것이다. **원래 진단은 아래에 남긴다.** **2026-08-25**([보고서](../../experiments/harness/2026-08-25-pipeline-zlib542-atom.md) §3 해석 ⑩). 기동 로그: `Default vLLM sampling parameters have been overridden by the model's generation_config.json: {'temperature': 0.7, 'top_k': 20, 'top_p': 0.8}`. 하네스는 `config/budgets.yaml`의 `sampling`에서 **`temperature`·`top_p` 둘만** 요청에 싣고(`adapters/openai_compat.py`의 payload), `RunRecord.sampling`의 스키마 `Sampling`도 **그 둘뿐**이다(`schemas/run.py`). → **`top_k: 20`은 하네스가 안 보내고, 서버가 모델의 `generation_config.json`에서 기본값을 적용하며, run 기록 어디에도 안 남는다.** evaluation.md §2.3이 “조건 간 비교에서 고정해야 하므로 RunRecord에 남는다”고 못박은 자리의 **구멍**이고, 성격이 나쁜 쪽이다 — 값이 **config에서 오지 않고 모델 파일에서 온다.** **지금 당장 깨지는 비교는 없다**: 8/22·8/23·8/25가 같은 모델·같은 서버라 셋 다 `top_k: 20`이 적용됐고 **그 run들끼리의 비교는 성립한다.** **깨지는 순간은 모델을 바꿀 때다** — `generation_config.json`은 모델마다 다르므로 B1(`qwen3-coder-30b-a3b`) 대 B3′(혼합) 비교에서 **선언하지 않은 샘플링 축이 조용히 갈린다.** **판단이 필요한 것**: **(a)** `Sampling`에 `top_k`를 추가하고 요청에 실어 서버 기본값을 덮는다 — 값을 정해야 하고 그 값이 이전 run과의 비교를 끊는다 **(b)** 덮지 않되 **기동 시 서버의 실효 샘플링을 읽어 `RunRecord`에 박제한다** — 비교는 안 끊기고 축이 기록에 드러난다 **(c)** 지금처럼 두고 “모델을 바꾸는 run은 샘플링 축이 미기록”이라고 적는다(이 항목). **2026-08-26 — 재현됐다.** 기동 로그가 `generation_config.json`이 서버 기본값을 `temperature 0.7 · top_k 20 · top_p 0.8`로 덮었다고 다시 적는다. `budgets.yaml`의 `sampling`은 `temperature 0.2 · top_p 0.95` 둘뿐이라 요청이 그 둘만 덮고 **`top_k: 20`은 하네스가 안 보내 서버 기본값이 적용된 채 `RunRecord`에 안 남는다.** 두 run이 같은 모델·같은 서버라 **8/25와의 비교 자체는 깨지지 않는다** — 문제는 기록이지 값이 아니다. **2026-08-28 — 예고한 "모델을 바꿀 때"가 왔고, 빠진 축이 하나가 아니었다**([track_a 보고서](../../experiments/harness/2026-08-28-pipeline-track-a-pwn003-atom.md) §2). **① 덮인 값이 넷이다.** 30B(NVFP4) 서버의 기동 로그는 `{'repetition_penalty': 1.05, 'temperature': 0.7, 'top_k': 20, 'top_p': 0.8}`이고 하네스가 보내는 것은 여전히 둘뿐이라 **`top_k`와 함께 `repetition_penalty: 1.05`도 기록 없이 적용된다.** 위 8/25·8/26 인용에 `repetition_penalty`가 없는 것은 값이 없었기 때문이 아니라 **보고서가 옮기지 않았기 때문이다** — 8/25 30B 서버 로그에 같은 줄이 있다. **이 항목이 말하는 미기록 축은 실제로 둘 이상이다.** **② 모델마다 갈린다는 것을 실측했다.** HF 캐시의 `generation_config.json` — `Qwen/Qwen3-8B`는 `temperature 0.6 · top_k 20 · top_p 0.95`를 들고 있고, `fdtn-ai/Foundation-Sec-1.1-8B-Instruct`·`ibm-granite/granite-3.3-8b-instruct`는 **bos/eos(+pad)뿐이라 서버가 덮을 값이 없다.** → **세 모델로 B1′를 돌면 Qwen3-8B만 `top_k 20`으로 돌고 나머지 둘은 vLLM 기본값으로 돈다.** "깨지는 순간"이 가설에서 관측으로 바뀌었다. **③ (a)의 반대 방향 손잡이가 있다** — 기동 로그가 직접 알려준다: `relaunch vLLM instance with --generation-config vllm`. 이것은 값을 실어 보내는 (a)가 아니라 **모델 파일의 기본값을 끄는 쪽**이고, 모델 간 차이는 지우지만 **그때 적용되는 vLLM 기본값이 무엇인지는 여전히 기록에 안 남아 (b)가 함께 필요하다.** **모델 비교 실험 전에 정해야 한다** — 지금 상태로 세 모델을 비교하면 샘플링 차이가 모델 차이로 섞인다
