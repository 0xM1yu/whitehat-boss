## 내용

### 기제 [코드 · origin/main 64bd566]

- 세 조회의 규칙 -> 앵커 파일에 정의가 있으면 그것, 없으면 저장소 전체에서 **이름이 하나뿐일 때** 그것(`definitions_of`·`callees_of`), 다른 파일 호출자는 대상 이름의 정의가 하나뿐일 때(`call_sites_of`)
- 이 규칙은 경로를 안 본다 -> `tests/`·`fuzz/`·`examples/`·`windows/` 아래 정의도 제품 코드 정의와 같은 자격
- 「하나뿐」이 표 단위라 더 샌다 -> `definitions_of`는 `macros`·`types`·`file_vars`만 본다. 제품 쪽이 **함수**이고 테스트 파일이 같은 이름을 매크로로 재정의하면 매크로 표에서는 테스트 쪽이 하나뿐이다

### 진행 중인 수정 -> 경로 강등 (PR #444)

PR #444(D102 수정)가 세 조회에 `demote_nonproduct`를 넣는다. `is_nonproduct_path`(디렉터리 이름 목록 `_NONPRODUCT_DIRS` + `fuzz*` 접두)로 비제품 정의를 「하나뿐」 판정에서 뒤로 민다. 삭제가 아니라 강등이고 앵커가 비제품 경로면 강등하지 않는다. 강등은 `auditor_definitions`를 켠 run만 쓴다 -> PR #443이 그 옵션을 기본값으로 켠다.

**이 항목은 그 강등을 중복하지 않는다.** 남는 것은 경로 이름이 추정이라는 점이다 -> 목록 밖 이름(`ios/`·`android/`·`unittests/`)은 안 걸리고, 목록 안 이름이 제품 코드인 저장소(`windows/`가 포팅 계층)에서는 필요한 정의가 뒤로 밀린다.

### 관측 [2026-10-03 · 로컬 · run ID 없음 · 강등 이전]

입력 -> FT Level 1 Auditor 입력 묶음 `ft_level1_auditor_inputs_defs_20261003.tgz`(270표본, `harness_commit` 09b4529, `auditor_options = [auditor_definitions]`). 블록 머리 `/* ===== file:a-b ===== */`의 경로를 디렉터리 이름 정규식으로 분류. 앵커 자체가 잡음 경로인 입력은 뺐다

| 앵커가 제품 코드인 입력 | 1,599,742 |
| 정의 블록 중 잡음 경로 | 626,979 / 10,062,808 (6.2%) |
| 잡음 경로 정의가 하나라도 실린 입력 | 305,280 (19.1%) · 178표본 |
| 슬라이스 함수 블록 중 잡음 경로 | 2,941 / 3,297,404 (0.1%) |

- 디렉터리별(정의·함수 합) -> `tests` 432,143 · `test` 82,621 · `windows` 27,568 · `fuzz` 21,213 · `samples` 19,520 · `ios` 9,335 · `docs` 9,076 · `android` 8,511
- 예 -> ImageMagick `Magick++/lib/Blob.cpp`의 `Magick::Blob::base64` 입력에 `MagickWand/tests/script-token-test.c:67`의 `#define RelinquishMagickMemory(p) (free(p),NULL)`이 붙는다. 실제 `RelinquishMagickMemory`는 `MagickCore`의 함수다(위 「표 단위」)
- 예 -> ndpi `ndpi_data_variance`에 `example/reader_util.h:129`의 `struct ndpi_entropy`, htslib `write_header`에 `test/sam.c:60`의 `fail`
- 측정 정규식과 `_NONPRODUCT_DIRS`는 다르다 -> 측정에만 `ios`·`android`·`unittest(s)`·`testsuite`·`vms`·`amiga`·`os2`·`msdos`·`beos`·`haiku`·`macos`·`darwin`·`wince`, 목록에만 `regress`·`contrib`·`vendor`·`third_party`·`xcode`·`msvc`
- ⚠ 미측정 -> 이 묶음은 피호출·호출자 옵션이 꺼져 있어 `callees_of`·`call_sites_of` 유입은 안 쟀다
- ⚠ 한계 -> 「그 정의가 틀린 대상인가」는 판정하지 않았다(잡음 경로 유입 수이지 오탐 수가 아님)

### 관계

- **[D102](D102.md)와** -> D102는 `definitions_of`의 조회 키이고 그 수정 PR #444가 경로 강등까지 세 조회에 넣는다. 이 항목은 강등 **다음**이다 -> 경로 이름 추정을 빌드 도달성으로 바꾸는 것
- **PR #443과** -> 그 PR 본문의 「이름 기반 오염은 따로 등재 예정」이 이 항목이다
- **[D95](D95.md)와** -> D95 선택지 (a)·(b)·(f)가 이 세 조회를 쓴다

## 왜 위험한가

- 모델이 테스트용 재정의를 제품 동작으로 읽는다 -> `RelinquishMagickMemory` 예는 해제 함수를 `free` 매크로로 보여 준다. 수명·해제 판정(C6)의 근거가 틀어진다
- FT 데이터에 그대로 쌓인다 -> 강등 이전 입력은 270표본 중 178표본에 섞여 있다
- 경로 강등 뒤에도 남는다 [추정] -> 목록 밖 비제품 경로와 목록 안 제품 경로. 양은 강등 뒤 재측정에서 나온다

## 선택지

- **(a) 경로 강등** -> PR #444가 구현 중. 이 항목에서 따로 하지 않는다
- **(b) 목록만 넓힌다** -> 위 측정에만 있는 이름을 `_NONPRODUCT_DIRS`에 더한다. 싸지만 여전히 이름 추정이다
- **(c) 빌드에 닿는 정의만 쓴다** -> 앵커 파일이 `#include`로 닿는 파일과 같은 빌드 단위의 정의로 후보를 묶는다. 경로 이름 추정이 없다. 인덱서에 include 그래프가 있어야 한다

(c)를 목표로 둔다. 강등 뒤 재측정에서 남은 양이 크면 (b)를 먼저 넣는다.

## 닫히는 조건

PR #444 머지 뒤 같은 270표본 입력을 다시 만들어 잡음 경로 정의 비율을 잰다. `callees_of`·`call_sites_of`도 옵션을 켜고 같이 잰다. (c)를 넣으면 그 비율과 함께 강등으로 밀린 제품 정의가 되살아나는지 본다. 옵션을 끈 run의 Auditor 입력은 바이트 동일해야 한다.
