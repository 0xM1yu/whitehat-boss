## 내용

### 기제 [코드 · origin/main 64bd566]

- 세 조회의 규칙 -> 조회 기준 파일(`definitions_of`는 앵커 파일, `callees_of`는 피호출을 찾는 그 함수의 파일 `target.file`)에 정의가 있으면 그것, 없으면 저장소 전체에서 **이름이 하나뿐일 때** 그것. 다른 파일 호출자는 대상 이름의 정의가 하나뿐일 때(`call_sites_of`)
- 이 규칙은 경로를 안 본다 -> `tests/`·`fuzz/`·`examples/`·`windows/` 아래 정의도 제품 코드 정의와 같은 자격
- 「하나뿐」이 표 단위라 더 샌다 -> `definitions_of`는 `macros`·`types`·`file_vars`만 본다. 제품 쪽이 **함수**이고 테스트 파일이 같은 이름을 매크로로 재정의하면 매크로 표에서는 테스트 쪽이 하나뿐이다

### 진행 중인 수정 -> 경로 강등 (PR #444)

PR #444(D102 수정)가 세 조회에 `demote_nonproduct`를 넣는다. `is_nonproduct_path`(디렉터리 이름 목록 `_NONPRODUCT_DIRS` + `fuzz*` 접두)로 비제품 정의를 「하나뿐」 판정에서 뒤로 민다. 삭제가 아니라 강등이고 앵커가 비제품 경로면 강등하지 않는다. 강등은 `auditor_definitions`를 켠 run만 쓴다 -> PR #443이 그 옵션을 기본값으로 켠다.

**이 항목은 그 강등을 중복하지 않는다.** 리뷰 단계에서 남는 것이 둘이었다.

- 강등이 표 하나 안에서만 걸린다 [코드 · PR #444 head d71822d, 가짜 v2 인덱스 재현] -> `definitions_of`는 행이 있는 첫 표에서 멈추고 `_product_first`는 그 표의 행끼리만 가른다. 제품 쪽이 함수(정의 표 밖)이거나 다른 표에 있으면 경쟁에 못 든다 -> 제품 함수 `RelinquishMagickMemory` + 테스트 파일 매크로는 강등을 켜도 테스트 매크로가 붙고, 제품 typedef `node`(types) + 비제품 매크로 `node`(macros)는 비제품 쪽이 나온다
  - ⏵ 2026-10-04 -> PR #444 d820530이 표를 가로질러 강등한다(아래 (a')). 그 이름의 제품 정의가 세 표나 제품 함수 어디든 있으면 비제품 행을 모든 표에서 뺀다 -> 위 두 예가 테스트로 박혔다(제품 쪽이 함수뿐인 `RelinquishMagickMemory`는 아무것도 안 싣는다). #444 머지로 이 잔여는 닫힌다
- 경로 이름이 추정이다 -> 목록 밖 이름(`ios/`·`android/`·`unittests/`)은 안 걸리고, 목록 안 이름이 제품 코드인 저장소(`windows/`가 포팅 계층)에서는 필요한 정의가 뒤로 밀린다

## 왜 위험한가

- 모델이 테스트용 재정의를 제품 동작으로 읽을 수 있다 [추정 · 영향 미측정] -> `RelinquishMagickMemory` 예는 해제 함수를 `free` 매크로로 보여 준다. 수명·해제 판정(C6)의 근거가 될 수 있다
- FT 데이터에 그대로 쌓인다 -> 강등 이전 입력은 270표본 중 178표본에 섞여 있다
- 경로 강등 뒤에도 남는다 [추정] -> 목록 밖 비제품 경로와 목록 안 제품 경로. 양은 강등 뒤 재측정에서 나온다

## 선택지

- **(a) 경로 강등** -> PR #444가 구현 중. 이 항목에서 따로 하지 않는다
- **(a') 표를 가로질러 강등한다** -> 강등을 켠 run은 세 표와 함수 정의(`_defined`)를 함께 보고 제품 정의가 있으면 비제품 행을 버린다. 위 표 단위 잔여를 닫는다. ⏵ 2026-10-04 PR #444 d820530이 구현(리뷰 반영). 같은 커밋이 `_NONPRODUCT_DIRS`에 `unittest(s)`·`testsuite`를 더하고 `fuzz*` 접두를 정확한 이름으로 좁혔다. `ios`·`android`는 제품 포팅 계층일 수 있어 안 넣었다
- **(b) 목록만 넓힌다** -> 위 측정에만 있는 이름을 `_NONPRODUCT_DIRS`에 더한다. 싸지만 여전히 이름 추정이다
- **(c) 빌드에 닿는 정의만 쓴다** -> 앵커 파일이 `#include`로 닿는 파일과 같은 빌드 단위의 정의로 후보를 묶는다. 경로 이름 추정이 없다. 인덱서에 include 그래프가 있어야 한다. ⏵ 2026-10-04 `definitions_of`에만 구현(아래 「⏵ 2026-10-04」 절)

(c)를 목표로 둔다. 강등 뒤 재측정에서 남은 양이 크면 (b)를 먼저 넣는다.

### 구현 [코드 · 이 브랜치]

- 인덱서 index-v4 -> 파일별 `#include` 표(`includes`: 경로 원문 · 꺾쇠 여부). 매크로 경로는 안 싣는다
- `definitions_of` -> 후보 여럿 · 앵커 파일에 없음 -> 앵커의 include 닫힘(깊이 8 · 파일 2,000, 정한 값) 안 후보가 **하나면** 그것. 0이거나 여럿이면 예전처럼 안 붙인다. v3 이하 인덱스는 이 단계가 없다. 「앵커」는 조회의 `near_file`이고 러너(`_auditor_source`)는 그것을 **실린 본문의 파일마다** 그 파일로 넘긴다 — 앵커 파일 하나로 부르면 다른 파일에서 실린 함수의 이름이 앵커의 include 닫힘으로 풀려 틀린 헤더의 정의가 붙었다(PR #485 리뷰, 4파일 재현).
  - 프롬프트 v7:60·`v4_t1:77`의 「a definition in the anchor's own file wins」는 본문이 한 파일일 때 정확하다. 여러 파일이면 본문마다 그 파일 기준으로 풀려서, 두 본문이 같은 이름을 서로 다른 정의로 풀면 둘 다 실린다(이긴다기보다 둘 다다). v7:60의 「that constant」는 물은 상수가 여럿이면 상수마다 앞뒤 5줄이다. 프롬프트는 안 고쳤다 -> PR #491의 v8이 v7을 바이트로 품어, 한 줄을 고치면 v8·핀 테스트와 연쇄한다(따로 정한다)
  - 남은 것 -> 이 PR은 정의 조회만 본문 파일 기준으로 바꿨다. `functions_named`(별칭이 부르는 함수)와 `_write_sites`의 `writes_of`·`field_writes_of`는 아직 앵커 파일 기준이라, 여러 파일 슬라이스에서 별칭의 정의는 본문 파일 기준 · 함수는 앵커 기준이다. 틀린 함수가 붙는지는 실행하지 않았다(이슈 후보)
  - 한계(선행 결함 · 미해결) -> 같은 범위의, 줄 머리 상수가 아닌 이름(typedef 이름·태그·비머리 상수)이 줄 머리 상수보다 먼저 처리되면 enum이 통째로 dropped되고 뒤따르는 상수는 겹침으로 안 실린다(수정 전과 동일). 처리 순서가 이름 정렬 다음에 슬라이스 줄에 나온 이름을 당긴 것이라, 슬라이스 줄에 타입 이름만 있을 때뿐 아니라 타입·태그 이름이 상수보다 정렬상 앞서는 enum(`enum AVPixelFormat` ↔ `AV_PIX_FMT_…` — `AVP` < `AV_`)은 둘 다 슬라이스 줄에 있어도 난다. **이 PR이 겨냥한 FFmpeg 꼴에서 상수 주변만 싣는 기능이 걸리지 않는다**(발동 빈도는 재지 않았다). 특성화 테스트 `test_limitation_a_type_name_asked_first_drops_the_whole_enum_and_hides_its_constants` · `test_limitation_a_type_name_that_sorts_before_its_constants_hides_them_on_the_slice`. 고치는 길은 크기로 dropped된 타입 이름 행을 `seen`에 안 올려 상수 행이 먼저 시도하게 하는 것이다(설계 변경이라 이 PR에서 안 함)
  - 한계(수정 전과 같은 침묵) -> 큰 enum에 상수를 더할 때 줄 머리 상수가 아닌 이름은 이미 실린 블록에 낱말로 있으면 보이는 것으로 읽는다. 정의가 아니라 언급(끝줄 값 `AAA_ALIAS = OP005_B,` · 창 안 주석)이어도 같게 읽어, 그 정의가 SOURCE에 없는데 `definitions_dropped`가 0일 수 있다. 특성화 테스트 `test_limitation_a_constant_only_mentioned_in_the_block_counts_as_shown`
  - 서식 -> 닫는 줄이 `}`이고 타입 이름이 다음 줄 `color_t;`인 enum은 그 이름을 줄 머리 상수로 읽어 넓히기가 수락된다. 옛 판은 같은 범위의 그 이름 행을 겹침으로 건너뛰었으므로, 이름 앞 5줄 창이 더해져 SOURCE가 옛 판과 바이트로 다르다(실제 인덱서 1건 · 411 -> 497자, 이 worktree와 `git archive HEAD` 사본에서 재 본 값 · 카운터는 `(1, 0, 1)` 그대로 · 필요 없는 6줄이 늘 뿐 해롭지 않다 — 드문 서식)
- 경로 해석 -> 따옴표면 포함 파일 디렉터리 기준 상대 경로 먼저, 아니면 경로 접미 일치(성분 최소, 동률이면 전부)
- 순서 -> 경로 강등(PR #444) 다음에 도달성. 강등이 비제품 행을 다 뺀 뒤 남은 제품 행이 안 닿으면 안 붙인다
- `callees_of`·`functions_named`·`call_sites_of`에는 안 넣었다 -> 함수 정의는 대개 `.c`에 있어 include로 안 닿는다. 이득은 헤더 `static inline`뿐

같은 브랜치의 다른 두 수정(D로 안 올림 -> 설계 판단 없는 버그):

- 같은 파일 정의 여럿 -> 실파싱으로 원인 확인. `typedef struct Z {…} Z;`는 `types`에 범위가 같은 행 둘(struct · typedef), `typedef struct X X;` + `struct X {…}`는 행 둘. 본문 없는 `struct X;`와 프로토타입은 행이 아니다. 읽는 쪽이 같은 범위를 하나로 세고 앞선 선언 행(v4 `forward`)은 **같은 파일에** 그 태그의 본문 행이 있을 때만 뺀다. 인덱서는 별칭 이름이 태그와 같은 맨 별칭(포인터·배열·`const` 아님)에만 `forward`를 달고, 읽는 쪽도 같은 파일의 본문 행을 다시 확인한다 -> 다른 파일의 같은 이름 행(`typedef int X;`)·이름이 다른 태그의 본문(`typedef struct Private Public;`)·포인터 별칭 때문에 지우면 엉뚱한 정의가 붙는다(#485 리뷰). 본문이 다른 파일에 있는 불투명 타입(`api.h`의 `typedef struct Y Y;` + `priv.h`·`impl.c`의 본문)은 두 행이 남는다(index-v3와 같다) -> 그다음은 앵커 파일의 행이 먼저고 아니면 앵커의 include 닫힘에 든 행이 하나뿐일 때 그것이다: 본문 파일이 앵커면 본문, 앵커가 typedef 헤더만 include하면 typedef 한 줄, **둘 다 닿거나 둘 다 안 닿으면 안 붙는다**(전 판은 forward 삭제 뒤 후보가 하나라 도달 불가한 파일의 본문도 붙였다). FFmpeg `MXFContext`가 어느 꼴인지는 안 봤다
- enum 상수 -> v4 `enum_constants`(범위 = 그 enum 정의 전체). 같은 enum 상수 여럿은 겹치는 범위라 러너가 한 번만 싣는다. 함수 본문 안 enum의 상수는 안 싣는다(지역 -> 싣으면 다른 함수의 같은 이름 사용에 그 값이 붙는다, #485 리뷰). 지역 판별은 선언자 사슬에 `function_declarator`가 있고 `type`이 `class`·`namespace` 식별자가 아닌 `function_definition`의 본문(함수 try 블록 포함)·람다 안이다. 파일·`namespace`·클래스·`extern "C"` 본문과 반환형의 enum은 싣는다 — tree-sitter가 `namespace`·`class`를 `function_definition`(본문이 `compound_statement`)으로 읽기도 해서(`.h`는 C 문법이라 C++ 헤더가 전부, `.cpp`도 `class API K {`처럼 매크로가 낀 머리) `compound_statement`만 보면 그 상수가 새고, 머리에 함수형 매크로 호출이 끼면(`class ALIGNAS(16) K {` · `namespace std _GLIBCXX_VISIBILITY(default) {` — `.h`·`.c`) 선언자가 `function_declarator`가 되므로 `type` 식별자까지 본다(#485 2·3라운드 리뷰). 못 빼는 지역 상수는 안 뺀다 -> 의심스러우면 행을 남긴다: `.c`·`.h`의 `TEST(a, b) {…}`(`.cpp`는 함수로 읽어 뺀다) · 함수 밖 문 표현식 · 참조 반환·변환 연산자·초기화 목록이 딸린 함수 try 블록(사슬을 못 따라간다)
