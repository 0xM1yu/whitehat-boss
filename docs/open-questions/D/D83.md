## 내용

**관측 [코드 · 2026-09-24 · origin/main `c301342`].** 아래는 전부 소스 대조다. **실관측은 0건이다** —
이 경로로 끝난 run도, 덮인 기록도 저장소에 없다(코드 추론, 미관측). 모델이 사실 블록의 ID를 그대로
베낀 관측은 있다(`run_20260904_0001` 표본 `find_0001` —
[2026-09-04 보고서](../../experiments/harness/2026-09-04-pipeline-zlib-serving-atom.md) §3). 그것은 모델이
따른 것이지 하네스가 막은 것이 아니다.

### 무엇을 대조하지 않나

- **Scout** — 노드가 `candidate_id`를 발급해(`scout.py:82`) 사실 블록에 싣지만(`:123`), 돌아온
  `Candidate`를 그대로 쓴다. v3는 `value.candidate`에 `scout_member`만 덮어 돌려주고(`:157-159`),
  v1·v2는 `value`를 그대로 돌려준다(`:162`). `candidate_id`·`run_id`·`artifact_id`·`state`를 발급값과
  맞춰 보는 줄이 없다.
- **Auditor** — `finding_id`·`missing_id`를 발급하고(`auditor.py:58-62`) 모델의 `Finding`을 그대로
  `ctx.create()`한다(`:71`). `_materialize_missing()`도 모델이 쓴 `finding_id`와 ID 목록을 그대로 쓴다
  (`:146-157`). 그렇게 만든 `blocking=True`를 내리는 경로도 없다 — [D65](D65.md)의 2026-09-24 절(해제 경로
  없는 blocking)이 그 결과를 든다.
- **하네스가 덮는 것은 둘뿐이다** — `produced_by`·`scout_member`(`context.py:294-325`). 그 도장의 논거
  (*"모델은 자기 model 이름도 prompt_version도 모른다"* — `:275-276`)가 발급 ID·초기 `state`에도 그대로 선다.
- **Critic은 이미 다르다** — `DecisionDraft`(`src/schemas/decision.py:48-69`)는 ID·`produced_by`를 안
  들고 `to_decision()`이 하네스 값으로 조립한다. 그 docstring이 이유를 적는다 — 모델에 provenance를
  맡기면 `produced_by.model`이 `"ChatGPT"` 등으로 나왔다(그 docstring이 드는 실측 — 이 항목이 재지 않았다).

### ① `state` → `IllegalTransition` → 매니페스트 없이 끝난다

`ctx.create()`는 `state_machine.create()`로 가고 `_lookup(kind, None, subject.state, reason)`
(`state_machine.py:232`)이 신규 생성 행을 찾는다. 행은 둘뿐이다 — C-1 `(없음 → candidate)`(`:122`)과
F-1 `(없음 → hypothesized, auditor_hypothesized)`(`:133`). 그런데 스키마가 받는 값은 더 넓다 —
`Candidate.state`는 `candidate`·`triaged`·`queued`(`src/schemas/candidate.py:14-18`), `Finding.state`는
`hypothesized`·`queued`·`validated`·`proven`·`reported`(`src/schemas/finding.py:18-24`)다. 모델이
`"triaged"`(Scout)나 `"queued"`(Auditor)를 쓰면 **파싱은 통과하고 생성에서** `IllegalTransition`
(`state_machine.py:179`)이 난다. `validated` 이상은 재현 명세·근거·경로 중 하나라도 없으면 스키마 검증기가
먼저 거부해 `SchemaParseError` 쪽으로 가고 그 갈래는 잡힌다 — **셋을 다 든 `validated` 이상은 검증기를
통과해**(`src/schemas/finding.py:149-175`) 같은 자리에서 `IllegalTransition`이 난다.

**그 예외를 잡는 곳이 없다.**

- 후보 단위 루프 `_triage_by_candidate()`(`runner.py:1411`·`:1433`)와 단계 단위 `_run_stage_for_all()`
  (`:1338`·`:1353`)은 `ModelGatewayError`·`SchemaParseError`만 잡는다.
- `run_pipeline()`의 `try`(`:655`)도 `BudgetExhausted`·`ModelGatewayError`·`_TooManyDrops`·`SchemaParseError`
  넷이다(`:657`·`:662`·`:670`·`:675`).
- `cli.execute()`(`cli.py:401-454`)와 `cli.run()`의 그 호출(`:673`)에 `try`가 없다.

그래서 `write_manifest()`(`runner.py:799`)와 `report.md`(`cli.py:674`)에 안 닿는다 — **매니페스트 없이
흘려 쓴 것만 남는다**: `trace.jsonl`과 그때까지의 `state.db`(와 run 중에 쓰는 `prompts/`·`heartbeat.json`)다.
sqlite 저장소는 `put()`마다 커밋하고(`sqlite_store.py:51`) `IllegalTransition`은 그 `put` 앞에서 나므로
(`state_machine.py:232` → `:233`) 그때까지 들어간 행이 `state.db`에 남는다 — 실서빙 프로필은 전부
`state_store: sqlite`다(메모리 저장소는 전 역할 Fake인 dev 셋뿐 — `config/profiles.yaml`).
`ModelGatewayError` 갈래의 주석이 막으려던 모양 그대로다 — *"이 갈래가 없던 동안에는 예외가 `write_manifest`
앞을 뚫고 나가 산출물이 하나도 안 남았고, zlib 때 `state.db`를 직접 열어야 했던 이유가 그것이다."*
(`runner.py:665-666`). 같은 모양의 실측 선례도 있다 — `SchemaParseError` 갈래가 생기기 전([D44](D44.md))
critic `SchemaParseError`로 죽은 `run_0002`의 산출물이 *"`report.md` **없음** · `run_manifest.json` **없음**
(trace와 state.db만 남았다)"*였다([2026-08-28 PWN-003 보고서](../../experiments/harness/2026-08-28-pipeline-track-a-pwn003-atom.md)
실험 2 결과 표).

### ② ID → 예외 없이 조용히 덮인다

저장소 `put()`은 `(kind, obj_id)` upsert다 — SQLite는 `ON CONFLICT (kind, obj_id) DO UPDATE`
(`sqlite_store.py:45-49`), 메모리는 딕셔너리 대입(`memory_store.py:21`). 모델이 다른 객체의 ID를 쓰면
**예외 없이 그 행을 덮는다.** `run_id` 열도 모델 값을 받는다(`sqlite_store.py:49`의
`getattr(obj, "run_id", None)`). 러너 누적기도 `finding_id` 키 딕셔너리라(`runner.py:1184-1188`) 같은
일이 난다. 트레이스는 두 ID로 갈린다 — `model_call`의 `subject_id`는 노드가 넘긴 발급값이고
(`context.py:242`의 이벤트), `transition`의 `subject_id`는 모델 값이다(`state_machine.create()`).

⚠ **그래서 이 항목은 두 갈래다 — 크래시(①)와 무음 오염(②).** 「예외를 잡으면 된다」는 ①만 푼다.

## 선택지

- **(가) 하네스가 도장을 찍는다.** `produced_by`·`scout_member`와 같은 자리에서 발급 ID·`run_id`·
  `artifact_id`·초기 `state`를 덮고, 모델 값이 발급값과 달랐으면 덮기 전에 trace에 남긴다(모델이
  사실 블록을 안 따랐다는 관측). ①②를 한 자리에서 닫는다. 대가: `model_copy(update=)`는 검증 우회라
  `state`에는 못 쓴다 — `transition()`이나 재검증이 필요하다(`context.py:290-291` 주석이 같은 경계를 적는다).
  Auditor가 적은 `missing_evidence` ID를 발급 `missing_id`와 대조하는 것도 이 자리다 — [D65](D65.md)의
  2026-09-24 절(해제 경로 없는 blocking)의 선택지 (다)와 같은 곳을 고친다.
- **(나) 예외 목록을 넓히고 부분 매니페스트를 쓴다.** `IllegalTransition`을 후보 단위로 잡아 그 후보만
  버리고(`_drop`), `run_pipeline()`에 마지막 방어선을 둔다. ①만 푼다 — ②는 그대로다.
- **(다) 모델 출력 스키마에서 그 필드를 뺀다.** `DecisionDraft`처럼 모델이 정하는 필드만 받는 초안
  스키마를 Scout·Auditor에도 두고 하네스가 조립한다. ①②를 원천에서 없앤다. 대가: 프롬프트 v1~v3의
  출력 계약(*"Copy these FACTS values exactly"* — `scout_memory/v3/prefix.md:32`)과
  [agent-contracts.md](../../agent-contracts.md)가 함께 바뀐다 — [evaluation.md](../../evaluation.md) §2.3
  규칙 4가 걸린다.

## 닫히는 조건

모델이 쓴 `state`·ID가 발급값과 달라도 run이 매니페스트까지 가고(①) 저장소·트레이스에 발급값만
남는 것(②)이 테스트로 고정되면 닫힌다. (나)만으로는 닫히지 않는다.
