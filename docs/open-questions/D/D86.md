## 내용

**2026-09-24 — [D10](D10.md)의 본문 끝 문단만 옮겼다**(D10은 ADR 0012 결정 6이 승인되면 닫힌다 — ⏵ 2026-09-25 승인됐고 닫혔다). D10(재평가 횟수를 어디에 보관하나)은
[ADR 0012](../../decisions/0012-harness-canon-v2.md) 결정 6이 재평가 경로를 폐기해 대상을 잃는데,
그 본문 끝의 resume·스키마 버전 문제는 재평가와 별개다 — 재평가가 없어져도 checkpoint/resume는
[architecture.md](../../architecture.md) §5 「횡단 구성 요소」의 Stateful Orchestrator 책임으로 남는다.
[D74](D74.md)→[D78](D78.md)·[D9](D9.md)→[D79](D79.md)와 같은 승계다. 옮긴 원문(D10 본문 끝):

> **resume를 지원하게 되면 스키마 버전 문제도 함께 풀어야 한다**: `adapters/sqlite_store.py`가 `model_validate`로
> 객체를 되읽으므로 구버전 `state.db`의 `RunRecord`는 필수 필드(`repo_dirty` 등) 누락으로 로드에 실패한다.
> 지금 안전한 이유는 호환성이 있어서가 아니라 `state.db`가 run 디렉터리 안에 있어 **구버전을 읽는 경로
> 자체가 없기** 때문이다. resume 설계 시 마이그레이션 또는 버전 게이트가 필요하다

**관측 [코드 · 2026-09-24 · origin/main `c301342`].** 위 원문을 그 트리에서 직접 열어 대조했다. **run에서
나온 값이 아니다** — 구버전 `state.db`를 되읽다 실패한 기록은 저장소에 없다(코드 추론, 미관측).

- **되읽기가 곧 검증이다.** `SqliteStateStore._load()`가 저장된 JSON을 `model_for(kind).model_validate(...)`로
  되돌린다(`src/adapters/sqlite_store.py:85-87`). 저장 형태가 JSON 한 컬럼이라(같은 파일 모듈 docstring의 선택이다 —
  [ADR 0001](../../decisions/0001-state-store-sqlite.md)은 저장 형태를 정하지 않는다) 필드가 바뀌어도 DDL은 그대로이고, 어긋남은 이
  되읽기에서 처음 드러난다.
- **빠진 쪽도 늘어난 쪽도 실패한다.** `RunRecord.repo_dirty: bool | None`(`src/schemas/run.py:184`)은 기본값이
  없어 필수다 — 바로 위 주석이 *"기본값을 두지 않는 것도 의도다"*라 적는다. 그 필드를 들인 `cee64fc`
  (2026-08-11)의 커밋 메시지가 이미 *"구버전 manifest는 파싱되지 않는다"*를 적었다 — 그 전의 `RunRecord` 행이
  원문이 든 예다. 반대로 기반 클래스가 `extra="forbid"`라(`src/schemas/common.py:62`) 스키마에서 필드를
  지우면 그 필드를 든 옛 행이 같은 자리에서 실패한다.
- **하네스 run 경로가 안전한 이유는 원문 그대로다.** run은 새 디렉터리를 원자적으로 선점하고
  (`src/cli.py:587`의 `mkdir(exist_ok=False)`) 그 안에 `state.db`를 새로 만든다(`src/adapters/factory.py:249` —
  `{artifacts_root}/{run_id}/state.db`). 지난 run 디렉터리를 이어받는 서브커맨드는 없다(`doctor`·`estimate`·
  `run`·`bench`·`gc` — `src/cli.py:860-889`).
- ⚠ **run 경로 밖에서는 옛 `state.db`를 연다 — 프로브 하나다.** `tools/probe/critic_output_budget.py`의
  `_load_findings()`(`:242-261`)가 같은 `SqliteStateStore`로 지난 run의 Finding·Evidence를 되읽는다(그 파일의
  사용 예가 `run_20260912_0001/state.db`다 — `:68`). 그 docstring은 캡슐을 안 읽는 이유를 같은 로드 검증으로
  든다 — 로드가 재검증이라 조립 때와 카운터가 다르면 `ValidationError`가 난다(#84, `src/tokens.py`의
  2026-08-28 정정 블록). 스키마가 바뀐 뒤의 파일을 이 프로브로 열면 같은 자리에서 실패한다(코드 추론,
  미관측). 원문의 「구버전을 읽는 경로 자체가 없다」는 **하네스 run 경로에 한해서다.**
- 슬라이서의 `--checkpoint`·`--resume`([slicer-README](../../slicer-README.md))은 슬라이서 자신의 체크포인트
  DB라 이 항목의 대상이 아니다 — README 예시의 파일 이름(`state.db`)이 같을 뿐이다. **다만 이 항목에 없는 게이트를
  그쪽은 든다.** resume 때 `run_contract`(원천 파일 해시 · 저장소 경로 · 설정 · `slicer*.py` 코드 해시 ·
  `joern_version` · `slice_version`)를 저장된 것과 대조하고, 어긋나면 `Checkpoint mismatch`로 거부한다(`slicer_checkpoint.py:87-92`의
  `bind()` · `slicer_pipeline.py:159-172`의 `prepare_checkpoint()`, 코드 해시는 `slicer.py`의 `job.code_hashes`) —
  아래 선택지 (b)의 저장소 안 선례다.

**이 문제를 전제하는 문서** — 셋 다 resume를 하네스의 책임이나 앞으로의 과제로 적는다.

- [ADR 0001](../../decisions/0001-state-store-sqlite.md) — 「대안과 기각 사유」 표의 「인메모리만」 행이 기각
  사유로 *"재평가·resume의 근거가 남지 않는다"*를 들고, 「후속」 마지막 불릿이 run 사이를 넘는 상태를
  [D10](D10.md)으로 가리킨다.
- [ADR 0002](../../decisions/0002-minimal-runner-langgraph-deferred.md) — 「결과」가 체크포인트·재개를 직접
  만들어야 한다고 적고, 「후속」 둘째 불릿이 *"병렬 실행·중단 재개를 도입하려면 그 재평가 루프부터 새로
  설계해야 한다"*고 적는다. 그 재평가 루프는 ADR 0012 결정 6이 폐기한다 — 재개의 선행으로 남는 것이
  이 항목이다.
- [architecture.md](../../architecture.md) §5 「횡단 구성 요소」 — Stateful Orchestrator의 책임에
  「checkpoint/resume」가 있다.

## 선택지

- **(a) 마이그레이션.** 스키마를 바꾸는 PR이 옛 행을 새 모양으로 옮기는 변환을 함께 싣는다. 옛 run을 이어
  돌 수 있다. 대가: `src/schemas/`는 여러 모듈이 붙는 결합점이라 변환이 스키마 변경마다 따라붙는다 —
  `sqlite_store.py` 모듈 docstring이 JSON 한 컬럼을 고른 이유가 DDL 마이그레이션으로 서로를 막지 않으려는
  것이었다([ADR 0001](../../decisions/0001-state-store-sqlite.md)은 저장 형태를 정하지 않는다).
- **(b) 버전 게이트(스키마 버전 필드).** `state.db`에 스키마 버전을 적고(메타 행이나 `RunRecord`의 필드)
  resume가 파일을 열 때 지금 버전과 다르면 로드 전에 거부한다. 옛 파일은 못 잇지만, 로드 도중
  `ValidationError`로 죽거나 타입은 같고 뜻만 바뀐 필드를 그대로 읽는 대신 여는 자리에서 이유를 대고 멈춘다.
  대가: 버전을 올릴 때를 사람이 판정한다 — 올리지 않고 필드를 바꾸면 게이트가 공회전한다. 저장소 안
  선례(위 「관측」 끝 불릿의 슬라이서 체크포인트)는 버전을 코드 내용 해시로 잡아 그 판정을 없앴다 — 대신 뜻이
  안 바뀐 수정에도 옛 파일을 거부한다. (a)와 배타가 아니다 — (a)도 파일이 어느 판에서 왔는지 알아야 변환한다.
- **(c) resume 비지원을 명문화한다.** 하네스는 run을 중단 지점에서 잇지 않는다고 정본에 적고,
  [architecture.md](../../architecture.md) §5의 「checkpoint/resume」와
  [ADR 0002](../../decisions/0002-minimal-runner-langgraph-deferred.md) 「후속」을 거기 맞춘다. 대가: 긴 실서빙
  run이 중간에 끊기면 처음부터 다시 돈다 — 지금 동작이다.
