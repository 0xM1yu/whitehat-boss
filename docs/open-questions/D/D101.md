## 왜 위험한가

- Auditor가 degraded 슬라이스와 온전한 슬라이스의 입력을 구별하지 못한다 -> 앵커 한 줄에서 나온 `SOURCE`와 데이터 흐름이 이어진 슬라이스의 `SOURCE`가 같은 모양이라, 판정(과 그것을 모은 데이터)이 입력 상태와 무관한 한 묶음으로 쌓인다
- 호출자 쪽 검사를 못 본 이유가 둘로 갈리는데 입력에서 안 갈린다 -> 역추적이 호출 지점이 CPG에 없는 파라미터(`entry_parameter`)에서 끝난 것(호출자를 못 찾음)과, 호출자가 있는데 입력에 안 실린 것(예: 호출자 창 옵션이 꺼짐). 검수 CSV의 C5(호출 전 검증 부족 920 — [D95](D95.md) 「검수 대조」)가 이 구분을 요구하는 비율은 안 쟀다
- 절단된 슬라이스를 온전한 것으로 읽는다 -> `truncated`·`truncation_reasons`가 하네스에 없다
- 필드가 없는 옛 슬라이스를 `truncated=False`(온전함)로 읽으면 안 잰 것을 잰 것으로 쓰는 것이다([CLAUDE.md](../../../CLAUDE.md) §0). 고칠 때 「없음」과 「모름」을 가른다

## 선택지

- **(a) 신호를 싣고 관측으로만 쓴다** -> 로더가 `analysis_kind` · `truncated` · `truncation_reasons` · `boundaries`를 기본값 있는 필드로 싣는다(`provenance` 배선이 선례 — `slices.py`의 #375 주석). 새 임계(기본 꺼짐)가 켜졌을 때만 `auditor_source` 이벤트(trace)에 **사유 목록**을 남긴다 -> 입력 바이트가 안 바뀌어 프롬프트 판이 필요 없다. 사유는 정적 사실에서만 만든다(LLM 단언 금지). 용도는 사후 집계 · 데이터 선별 · 게이트다. 꺼진 run은 바이트 동일해야 한다. ~~수정 진행 중(브랜치)~~ ⏵ 2026-10-10 — PR #448로 머지(2026-10-03 `fed79f37` · 그 PR 본문은 `Refs #438`이고 「(b)가 남아 닫지 않는다」고 적음). 임계 `auditor_source_gate`는 2026-10-05 `c07a5bc7`부터 `config/budgets.yaml`에서 1(`:671`). 아래 「닫히는 조건」의 재구성 대조는 저장소에 기록 없음(미실측) · (b)는 미착수(배선 판 `prompts/auditor/v11/prefix.md`에 슬라이스 상태 서술 없음)
- **(b) (a) + 프롬프트에 노출** -> 모델이 입력의 상태를 보고 판정한다. 새 프롬프트 판(~~다음 번호는 v7 — `prompts/auditor/`는 v6까지 있다~~ ⏵ 2026-10-05 v7(#349)·v8(#419)이 쓰였다 — 지금은 v8까지 있고 다음 빈 번호는 `v9`다. ⏵ 2026-10-06 — v9(`auditor_guards` 서술)·v10(v7 전면 재작성)도 쓰였다 — 디스크에 `v10`까지 있으니(`prompts/auditor/` 디렉터리 목록 — `v4_t1`은 v4의 미배선 변형이라 `v<n>` 번호를 안 쥔다) 다음 빈 번호는 `v11`이다)이 필요하고 입력 바이트가 바뀌어 [evaluation.md](../../evaluation.md) §2.3의 재측정이 걸린다. 입력이 길어지는 정도와 판정 분포가 어느 쪽으로 움직일지(예: 판단 불가 쪽)는 안 쟀다
- **(c) 안 고침** -> `degraded`는 Scout에만 간다. 위험 절 그대로

## 닫히는 조건

선택한 안을 넣고 FT 입력(옵션 끔)을 같은 방식으로 재구성해, 신호별(`degraded` · `truncated`+사유 · `entry_parameter`)로 건수를 세어 슬라이서 산출물(`slices.json`)의 집계와 맞는지 본다(degraded 96.8%가 그대로 재현되는 것 포함). 옵션을 끈 run의 Auditor 입력이 바이트 동일한 것을 같이 확인한다. (b)를 고르면 켠 run과 끈 run을 같은 표본으로 짝 비교한다.
