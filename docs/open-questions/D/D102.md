- 걸러 낼 재료는 있는데 안 쓴다 -> index-v2는 `locals`(파일 -> 함수 -> 이름 -> [선언 줄], **파라미터 포함** — `indexer.py` 모듈 docstring의 표)와 `fields`를 이미 갖지만(`V2_TABLES`, `index_graph.py:98-108`) `definitions_of`는 `DEFINITION_TABLES` 셋만 읽는다

- 이 경로에 지금 닿는 곳 -> 옵션은 기본 0이고(`config.py`의 `auditor_definitions`) `config/`에 켜진 값이 없다(grep 0건). 정본 Auditor 프롬프트 v6의 meta에는 `source_options`가 없어 옵션을 켠 설정은 `cli`의 run·doctor가 막는다(`config.py` 주석 · `cli.py:_check_source_options`). 닿는 것은 `source_options`를 든 `v4_t1`과 오프라인 재구성([D95](D95.md)의 s500 재측정처럼 `_auditor_source`를 직접 부르는 도구)이다. ## 왜 위험한가

- `auditor_definitions`를 켠 입력에 그 코드가 가리키지 않는 정의가 섞인다 -> 위 1개 저장소 후보 기준으로 확정 오탐이 하한 9%, 비제품 경로 유입이 21%다. 모델이 지역 변수 `za`의 선언을 다른 파일의 전역 `za`로 읽을 수 있다. 실제로 실린 비율과 판정에 미치는 영향은 안 쟀다
- 같은 cap을 먼저 먹는다 [추정] -> 정의는 `(파일, 줄)` 순 first-fit이라 앞 경로(예: `examples/`)의 오탐이 먼저 들어가면 뒤 경로의 필요한 정의(버퍼 크기·필드 배치 — [D95](D95.md)가 버퍼 용량(C5)과 직결이라 적은 것)가 `definitions_dropped`로 밀릴 수 있다. 코드의 정렬·first-fit 순서에서 나온 추정이고 실린 수 기준으로는 안 쟀다
- 켜는 날 오염이 기본이 된다 -> [D95](D95.md)의 채택 조합이 이 옵션을 든다. 켜기 전에 이 조회 키를 고치지 않으면 켠 run의 입력이 처음부터 오염된 채로 쌓인다

## 선택지

- **(a) 조회 키를 고친다** -> `used`를 함수별로 만들어 그 함수의 지역·파라미터(index-v2 `locals`)와 필드로만 쓰인 토큰(`->x`·`.x`)을 뺀다 · 슬라이스 줄에 나온 이름의 정의를 먼저 싣는다 · 비제품 경로를 **강등**(삭제 아님 — 앵커 파일 자신의 디렉터리는 예외)해 「저장소에서 하나뿐」 판정에서 비제품 행을 무시한다. 옵션이 꺼진 경로는 바이트 동일이고 `auditor_definitions=1`의 출력은 바뀐다(PR 본문에 적는다). 인덱스에 `locals` 조회를 더하면 `definitions_of`가 지나는 주입 자리(`factory.py`·`context.py`·`runner.py`)를 따른다. 수정 진행 중(브랜치)
- **(b) 비제품 정의를 삭제한다** -> 규칙은 단순하나 비제품 판정(디렉터리 이름 목록)이 이 저장소 구조에 맞춘 추정이라, 판정이 틀린 저장소에서는 필요한 정의가 사라진다. 강등은 잘못 판정돼도 순서만 바뀐다. 앵커가 `fuzz/`·`examples/`·테스트 디렉터리에 있는 표본에서는 같은 디렉터리의 정의까지 사라진다
- **(c) 옵션을 끈 채 둔다** -> 오염은 없으나 매크로·구조체 정의(버퍼 용량의 근거)가 계속 안 실린다 — [D95](D95.md)가 든 문제가 그대로다

## 닫히는 조건

선택한 안을 넣고 같은 재생(`definitions_of`를 모든 함수에 돌려 확정 오탐·비제품 유입을 다시 셈)에서 확정 오탐이 0이 되고 비제품 유입이 줄어드는 것을 보고, **다른 저장소**(특히 `contrib/`·`fuzz/`·플랫폼 디렉터리가 큰 곳)에서도 같은 수를 잰다. 옵션을 끈 run의 Auditor 입력이 바이트 동일한 것을 같이 확인한다. 확정 오탐은 정적 판정(지역 선언 여부)이라 LLM 재검수를 쓰지 않는다.
