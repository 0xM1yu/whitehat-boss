## 내용

**2026-08-29 (a)로 해소.** `src/cli.py`가 `_tool_runner_overrides`로 프로필 선언값(`load_config(profile).profile.adapters.tool_runner` — 오버라이드 적용 **전** pristine 값)과 비교해 **값이 바뀐 run에만** 경고를 붙인다. `run`의 stderr 경고와 `doctor`의 `_override_note`가 같은 술어를 쓴다. 회귀 테스트가 같은 값→무경고·다른 값→경고를 잠근다(`tests/test_bench_apply.py`). **원래 진단은 이력으로 남긴다.** **2026-08-28**([run A 보고서](../../experiments/harness/2026-08-28-runA-harness-validation-atom.md) 메타). `run_20260828_0002`가 `[WARN ] 프로필과 다른 도구 런타임으로 돌았다: docker`를 냈는데 **`b1_single`의 선언값도 `docker`다**(44392a6 시점 확인). **기제**: `cli.py`의 경고가 `if args.tool_runner is not None:`만 보고 선언값과 비교하지 않는다. **왜 중요한가**: 그 경고가 [ADR 0005](../../decisions/0005-tool-runner-override.md)와 [evaluation.md](../../evaluation.md) §2.3 규칙 2의 **예외 신고**다. 예외가 아닌 run이 예외로 신고되면 규칙 2가 무뎌지고, 보고서 메타의 "프로필 선언값 / 실제 사용값"을 쓰는 사람이 실제로 오도된다(run A 보고서를 쓰며 한 번 걸렸다). **`RunRecord.tool_runner`는 정확하다** — 틀린 것은 경고 문구뿐이라 사후 재구성은 가능하다. 선택지: **(a)** 선언값과 다를 때만 경고한다 — 한 줄이고 문구가 사실이 된다 **(b)** 문구를 "도구 런타임을 명시했다"로 바꾼다 — 비교를 안 해도 되지만 예외 신고의 뜻이 약해진다 **(c)** 같을 때는 다른 문구로 알린다 — 명시 사실 자체는 남기고 예외 여부를 가른다
