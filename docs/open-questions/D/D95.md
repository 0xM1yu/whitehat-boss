> 인덱스: [docs/open-questions.md](../../open-questions.md) · 추적 미러: [#349](https://github.com/0xM1yu/whitehat-boss/issues/349)

## 내용

### 기제 [코드]

`_auditor_source`가 Auditor `SOURCE`를 만드는 규칙 (ADR 0012 결정 1-b = 넓은 (i))
- entry 줄을 품는 함수 원본 -> 맨 앞
- 슬라이스 줄마다 그 줄을 품는 가장 좁은 인덱스 심볼 -> (파일, 시작 줄) 순으로 붙임, 15,000자 넘으면 뒤는 버림
- 어느 함수에도 안 드는 줄(매크로·전역·구조체) -> 세기만 하고 안 실음

-> 붙는 기준이 「슬라이스 줄이 지나간 함수」뿐. 슬라이스는 데이터 흐름만 따라가므로
- 호출 줄만 슬라이스에 있고 본문 줄은 없는 피호출 함수(검증·길이 계산·래퍼) -> 안 붙음
- 호출자 쪽의 검사(`if (len > MAX) return;` 뒤 호출) -> 슬라이스가 안 가면 안 붙음

### 관측 [2026-10-01 · s500 handoff · 로컬 분석]

데이터 -> `harness_sample500_v1v3`(vuln 500 · patch 500 · normal 500)을 하네스(`b52f847` · Joern 4.0.605)로 자른 Auditor 입력 81,748건(2026-09-29 하네스팀 산출). **GT 파일 하나만 잘랐으므로 다른 파일 맥락은 원래 없음** -> 아래는 파일 안에서의 수

측정 단위 -> 표본마다 GT를 보는 입력(`gt_relevant`) 중 GT 지점을 가장 많이 싣는 입력 하나

| | vuln | patch | normal |
| --- | --- | --- | --- |
| 측정 표본(GT 보는 입력 있음) | 419 | 422 | 433 |
| **같은 파일에 정의된 함수를 부르는데 본문이 입력에 없음** | 239 (57%) | 241 (57%) | 250 (58%) |
| root_cause 줄이 실린 함수 안 | 346 (83%) | 351 (83%) | - |
| sink 줄이 실린 함수 안 | 351 (84%) | 355 (84%) | - |
| 대상 함수가 실림 | - | - | 409 (94%) |
| 15,000자 상한 때문에 GT 함수가 빠짐 | root_cause 1 · sink 2 | 1 · 3 | 0 |

- GT 함수는 대체로 실림(83~94%) -> 빠지는 것은 **옆 함수**. 세 종류가 같은 모양 -> 라벨 문제가 아니라 빌더 구조
- 본문 누락은 **하한** -> 「정의돼 있다」를 그 표본의 다른 입력이 실은 함수로만 앎. 어느 입력에도 안 실린 파일 안 함수는 못 셈
- 빠진 GT 지점(vuln, 범위 앎) 중 실린 함수와 1단계 관계 -> root_cause 17/43(호출자 12 · 피호출 5) · sink 15/42(호출자 6 · 피호출 9). 나머지는 2단계 이상
- 상한은 GT를 거의 안 자름 -> vuln·patch의 GT 보는 입력 2,953건 중 1,007건(34%)이 함수를 1개 이상 버리지만, GT 함수를 버린 표본은 1~3
- GT 보는 입력이 없는 139표본 중 57(vuln 28 · patch 25 · normal 4)은 GT 함수가 실제로는 실림 -> handoff의 `gt_relevant`(슬라이스 줄 ±2)가 Auditor가 보는 것(함수 통째)보다 좁음
- 함수 이름·호출은 정규식으로 뽑음(인덱서 아님) · run ID 없음 · 원자료·스크립트 저장소 밖 로컬 `measure_results/s500/`

## 왜 위험한가

- Auditor가 `memcpy(buf, p, len)`은 보는데 `len`을 만든 `read_len()` 본문은 못 봄 -> 검사가 있는지 모름 -> 원본은 안전한데 위험해 보이거나, 판단 불가로 `need_evidence`
- FT 데이터가 이 빌더로 만들어짐 -> 학습 입력도 같은 맥락 결손. 따로 더 좋은 입력으로 학습하면 실사용 입력과 어긋남 -> 빌더 자체를 고쳐야 함

## 선택지

- **(a) 피호출 함수 본문 1단계** -> 실린 함수 범위 안의 호출(인덱스 호출 그래프) -> 정의된 함수 본문을 붙임. 순서 = entry → 슬라이스가 지나간 함수 → entry가 부르는 함수 → 나머지가 부르는 함수. 큰 함수는 건너뜀. 57% 문제를 직접 겨냥
- **(b) 호출자 호출부 창** -> entry 함수를 부르는 호출 지점 앞뒤 N줄. 호출자 쪽 검사 겨냥. 함수 통째보다 작음
- **(c) 상한 재설정** -> (a)(b)로 커지는 만큼 15,000자를 올리거나 Auditor 토크나이저 토큰 기준으로. 창 −출력 −프롬프트 안에서. 입력 토큰 실측과 함께
- **(d) 안 고침** -> FT 데이터 선별로만 대응(GT 함수 실림 기준 재판정 · vuln=patch 동일 입력 짝 제외). 맥락 결손 자체는 남음

⚠ (a)(b)는 ADR 0012 결정 1-b(「슬라이스가 걸친 함수의 원본 전부」)를 넓힘 -> 그 결정의 개정이 필요. 오케스트레이터는 어댑터를 import 못 하므로 호출 그래프 조회는 `symbols_for`처럼 `RunContext`에 주입

## 닫히는 조건

선택한 안을 넣고 같은 s500 입력(GT 파일 · handoff `slices.json`)으로 수정 전후를 다시 잼 -> 본문 누락률 · GT 지점 실림률 · 입력 크기(글자·토큰)를 나란히. 결정 1-b 개정이 함께 온다.
