## 내용

**⏸ 남은 (1) 열거 강제는 모델 선정 대기로 보류 (2026-08-30, 5차 회의).** (2) 필드 순서는 닫혔고, (1) `Literal` 강제는 v2 프롬프트의 emit 분포 관측이 필요한데 그건 v2로 돌 모델이 정해져야 한다. **2026-08-29 — (2)에 첫 관측이 생겼고 (1)은 그대로다** ([v2 스모크 보고서](../../experiments/harness/2026-08-29-prompt-v2-smoke-atom.md) §6·§3). **(2)**: 서버 직접 프로브(`Finding` 스키마 · `strict: true` · 하네스 밖)에서 모델이 낸 10개 키가 선언 14개 순서의 **부분수열**이었다(자리 1·2·3·4·5·7·9·10·13·14 — 단조 증가). **순서를 어긴 자리가 0이다.** 다만 이것은 "모델이 지켰다"이지 "xgrammar가 강제한다"가 아니다 — 가르려면 **순서를 뒤집은 스키마로 대조**해야 하고 그것은 안 했다(표본 1건). 순서를 맞춰 두는 판단은 그대로 유지되고 근거가 하나 붙는다. **(1)**: v2 스모크의 emit 분포가 `triggerable` **1종 ×6**이다. 다섯 값 중 하나만 봤으므로 **닫는 조건("emit 분포 관측")이 충족되지 않았다** — 여기서 `Literal`로 좁히면 못 본 네 값이 Finding을 통째로 떨군다. **(b) 유지.** 분포를 넓히려면 다른 대상·다른 조건의 v2 run이 필요하고 그것은 D54에 걸려 있다. 아래는 등재 당시 기록이다. **2026-08-28 PR #53 리뷰 INFO로 등재.** `src/schemas/finding.py`의 `trigger_status` 주석이 두 가지를 **실제 emit 분포를 본 뒤로** 미뤄 뒀다 — **(1)** `Literal`/enum으로 좁혀 강제하는 것 **(2)** 필드 순서를 `state` → `path` → `trigger_status` → `confidence` → `rca_draft` → `cwe` → … 로 재배치하는 것. **(2)는 2026-08-29 적용했다** (PR #53). 미룬 근거가 "xgrammar가 property 순서를 강제하는지 확인 뒤"였는데, **확인 전에 해도 해롭지 않다**는 것이 판단이다 — 강제하면 의도한 효과가 나고 안 하면 무효과이지 깨지는 경우가 없다. 순서는 `prompts/auditor/v2` prefix 90-105행이 요구하는 것과 같게 뒀고 `agent-contracts.md`의 예시도 맞췄다. **다만 그 순서가 생성까지 강제되는지는 여전히 미측정이고**, v2 프롬프트로 도는 첫 run이 그 답을 준다. **(1)은 열려 있다.** 닫는 조건이 emit 분포 관측인데 그것이 D52에 막혀 있었고, D52가 닫히면 v2 smoke 한 번이 분포를 준다. 분포를 보기 전에 좁히면 못 본 값이 finding을 통째로 떨군다. 선택지: **(a)** v2 smoke의 분포를 보고 `Literal`로 좁힌다 **(b)** 좁히지 않고 `str`로 둔 채 값 집합만 문서로 강제한다 — 검증이 안 되지만 떨구지도 않는다 **(c)** 좁히되 미지값을 `no_signal`로 흡수한다 — 관측을 잃는다
