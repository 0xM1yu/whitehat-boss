# D66 — Evidence.location을 채우는 코드가 없어 게이트 E1의 위치 판정과 신호 우선순위가 심볼 아닌 artifact 단위다

| 상태 | 관련 문서 |
| --- | --- |
| 열림 | `src/schemas/evidence.py`(:33), `src/orchestrator/gate.py`(:126~129), `src/adapters/container_tools.py`(:280·866), `src/orchestrator/nodes/signals.py`, `src/orchestrator/runner.py`(:48·820·829), `CLAUDE.md` §5, [architecture.md](../../architecture.md) §4 |

> 인덱스: [docs/open-questions.md](../../open-questions.md) · 작업 추적은 GitHub Issue

## 내용

**관측.** `Evidence.location`(`evidence.py:33`, `Location | None`, 기본 `None`)을 **채우는 코드가 저장소에 없다.** `container_tools._write`(:866)가 location 없이 Evidence를 만들고, 도구 출력을 파싱해 위치를 뽑는 코드도 없다 — 로그 텍스트(`sections`)만 저장한다. Fake 도구도 같다. 이 사실은 `runner.py:48` docstring과 `CLAUDE.md` §5가 이미 못박고 있다("Evidence.location을 채우는 코드가 없어 판정이 구조적으로 거짓").

**결과 1 — 게이트 E1의 위치 분기가 죽어 있다.** `gate.evaluate`의 `location_ok`(`gate.py:127~129`)는 `ev.location is not None and ev.location.overlaps(cand.location)`인데, `ev.location`이 항상 `None`이라 **`location_ok`은 항상 거짓**이다. 그래서 E1의 `p1 = static_ok or location_ok`는 사실상 `static_ok`(STATIC 신호 유무)로만 성립한다 — 정적 신호가 없는데 위치가 맞아 올라와야 할 후보는 E1로 못 오른다.

**결과 2 — 신호 주도 우선순위가 파일 단위다.** `runner.py:44~45`가 "신호가 붙은 artifact의 심볼을 큐 상위"로 두려 하는데, 신호 판정이 artifact 단위다(`:820` `signal = any(evidence.kind is STATIC ...)`가 boolean, `:829` fallback이 `Location(file=artifact.path)`). 즉 **같은 파일의 모든 심볼이 같은 우선순위**를 받는다 — "신호 붙은 심볼 먼저"가 심볼 단위로 실현되지 않는다.

**기제 — 왜 "도장 한 줄"이 아니라 설계 판단인가.** Evidence는 **도구 실행당 하나**다(`signals.py`가 artifact마다 semgrep·clang-tidy·build를 각각 한 번 부르고 각각 Evidence 하나). 그런데 semgrep은 `--json`(`container_tools.py:280`)으로 **한 파일에서 여러 위치**를 찾는다. `location: Location | None` **하나**에 여러 발견이 안 담긴다. 그리고 후보 자신의 위치를 그대로 도장 찍으면 `overlaps`가 자명하게 참이 되어 **무의미**하다(아무 근거나 E1로 승격). 그래서 "어느 granularity로 Evidence를 낼지"를 먼저 정해야 한다.

**왜 그냥 두면 안 되나.** 게이트 E1의 위치 일치 판정이 구조적으로 거짓이라 제거율 해석에 들어가고(evaluation.md §5.1), 신호 주도 슬라이싱의 정밀도가 심볼이 아니라 파일에 머문다. 리스트럭처(#146 평의회가 든 "인덱서가 헤더를 건너뜀 · 타깃 불일치")와 같은 축 — **신호를 심볼에 정확히 붙이는** 정밀도 문제라, 새 아키텍처의 신호·인덱서 결정과 함께 정하는 것이 자연스럽다.

**선택지.** **(a)** semgrep 발견당 Evidence 하나(각자 `location`) — 도구가 Evidence를 1→N으로 내고 러너·게이트가 그것을 받게 한다. 신호 우선순위가 심볼 단위가 되고 E1 위치 분기가 산다. 대가: ToolRunner의 Evidence 방출 방식과 소비자(러너·게이트)가 함께 움직인다. **(b)** `Evidence.location`을 위치 **집합**으로 + `overlaps`를 any-match로 — 스키마 하나 바꾸고 파싱만 추가. 대가: "Evidence 하나 = 도구 하나"는 유지되나 위치가 여럿이라 근거 단위가 흐려진다. **(c)** 러너 우선순위만 semgrep JSON을 따로 읽어 심볼 단위로 — 게이트 E1의 위치 분기는 **여전히 죽은 채** 부분만 해소. 대가: 파싱이 두 곳(러너·도구)으로 갈릴 위험.

## 상태

착수 전 · **결정 대기(granularity a/b/c).** 리스트럭처의 신호·인덱서 정밀도 결정과 묶여 있어, 그와 함께 정하는 것을 권한다.
