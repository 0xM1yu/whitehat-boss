## 내용

### 기제 [코드]

- 검증 벤치마크 = CyberGym Level 1 -> 과제 입력이 취약 저장소 + 취약점 설명(`task_loader.py` 모듈 docstring). 결정은 2026-09-30([ADR 0012](../../decisions/0012-harness-canon-v2.md) Phase 7)
- 설명이 닿는 곳 -> `run --description-file` -> 캡슐 `vuln_description` 섹션 -> Scout·Auditor·PoV 프롬프트의 텍스트(`retrieval.run`, `f58e244` 2026-09-30 PoV 배선)
- 설명이 안 닿는 곳
  - 슬라이서 -> run 밖에서 저장소 전체의 앵커 후보를 전부 찾음. 설명을 받는 인자가 없음(`slicer.py` CLI)
  - Auditor `SOURCE` -> 슬라이스 + 인덱스만 봄(`runner._auditor_source`)
- 순서 문제 -> 슬라이서 설계·recall 개선([D90](D90.md)·[D91](D91.md)·[D94](D94.md))은 설명 없는 평가셋 기준이었고 벤치마크 결정이 그 뒤. 설명을 슬라이싱에 쓸지 검토·거절한 기록은 저장소에 없음

### 관측 2 — 설명이 고친 위치를 가리키는 비율 [2026-10-02 · CyberGym 공개 과제 · 로컬 분석]

데이터 -> HF `sunblaze-ucb/cybergym` @ `bde190d` 과제 1,507개 중 `description.txt`·`patch.diff`를 다 받은 1,503개. GT 대리 = `patch.diff`가 고친 C/C++ 파일·함수

| 설명이 언급하는 것 | 과제 | 비율 |
| --- | --- | --- |
| 고친 파일(확장자 없는 이름 포함, 4자 이상) | 469 | 31.2% |
| 고친 함수 이름(hunk 머리·정의 줄에서 뽑은 함수) | 246 | 16.4% |
| 고친 파일, 또는 고친 hunk에 나오는 식별자 | 921 | 61.3% |
| 파일·함수 이름을 무엇이든 언급 | 1,076 | 71.6% |

- 61.3%는 하한 -> hunk 머리가 없는 패치(hg diff 등)는 함수를 못 뽑음. 설명이 고친 함수를 정확히 불러도 놓치는 형태가 있음(arvo 10013 `QuantumTransferMode()`)
- 약 28%는 이름 없이 증상·모듈만(예: arvo 14537 "The RAR5 reader ...")
- 고친 위치 ≠ 터진 위치일 수 있음 -> 대리 지표
- 스크립트 저장소 밖 로컬(`count_hint.py`·`count_hint2.py`) · run ID 없음

## 왜 위험한가

- 시간 -> 저장소 전체 후보를 다 자르는 비용이 표본당 수십 분~상한. 1,500표본이 며칠(계산값)이라 FT·검수용 수만 표본 생성이 프로젝트 기간 안에 안 끝남
- 상한 아래 recall -> 상한에 걸리면 남은 후보가 앵커만 남는 degraded로 나옴. 그쪽에 GT가 있으면 놓침. 지금은 후보 처리 순서가 설명과 무관
- 잡음 -> 슬라이스 수천 개가 Scout로 감. 설명과 맞는 슬라이스를 앞에 둘 근거가 하네스에 없음
- 데이터 분포 -> Level 1 run의 입력은 설명 포함인데 지금 만드는 입력·측정은 설명 없음

## 선택지

- **(a) 범위 제한** -> 설명이 가리키는 파일·디렉터리만 Joern에 넣음. 가장 빠름. 설명이 위치를 안 주는 약 30%는 엉뚱한 범위 -> recall 하락. 설명 없는 run의 경로를 따로 둬야 함
- **(b) 우선순위** -> 저장소 전체 후보는 그대로 두고 설명과 맞는 후보(파일·함수 이름 일치)를 먼저 슬라이싱, 시간 예산이 남으면 나머지. Scout에도 그 순서로. 후보 집합이 같아 recall이 안 줄고 상한 아래에서는 오름. CPG는 저장소 전체라 초대형 저장소 비용은 안 풀림
- **(c) 범위 + 확장** -> 설명이 가리키는 파일에 그 파일이 부르는·불리는 파일까지. (a)와 (b) 사이. 확장 규칙을 정해야 함
- **(d) 안 고침** -> 지금처럼 설명은 캡슐 텍스트로만

## 닫히는 조건

선택한 안을 넣고 같은 표본으로 재잼 -> 표본당 슬라이싱 시간 · GT 포착(level-2 줄 기준) · 상한에 걸린 표본의 GT 포착을 수정 전후로 나란히. 설명이 위치를 안 주는 과제에서 GT 포착이 안 줄어야 함
