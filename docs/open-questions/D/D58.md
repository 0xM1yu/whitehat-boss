> 인덱스: [docs/open-questions.md](../../open-questions.md) · 작업 추적은 GitHub Issue

## 내용

PR #107이 `declared_sampling_by_role`의 docstring을 새 계약("선언 없음" vs "못 읽음" 분리)에 맞게 고쳤는데, **같은 사실을 서술하는 인접 주석 셋이 옛 판본 그대로**라 저장소에 두 판본이 공존한다(CLAUDE.md §2.3). 셋 다 PR #107 이전부터 그러했던 것이라(회귀가 아님) 별건이다.

**대상 셋** — (1) `factory.py:360-361` "Fake·`source` 없는 모델은 빠지고" → 파일 없음·경로 리졸브 실패·파일 깨짐도 빠지는데 안 적힘. (2) `run.py:223-226` 같은 누락(#106이 `profile` 필드를 넣으며 40줄 밀렸다 — 인용문 자체가 185→225). (3) `run.py:84` "`read_declared_sampling`이 검증 실패 시 **전부 버린다**" → **거짓**이다(`kept` 루프가 이미 낱개로만 버린다). 셋째가 특히 나쁘다 — 그 문장이 `ModelSampling.top_k`가 `0`·`-1`을 정상 선언으로 받게 넓힌 **근거로** 쓰이는데 근거가 사실과 다르다. 넓힌 결정 자체는 옳고(정상 선언을 스키마 밖으로 밀면 그 모델 기록이 통째로 사라진다) **논거만 낡았다**.

**왜 중요한가**: 지표가 틀리는 게 아니라 **읽는 사람이 틀린다** — `read_declared_sampling`의 반환 계약이 `None`(못 읽음)/빈 `ModelSampling()`(읽었으나 선언 없음)으로 갈렸는데, 이 셋을 읽은 사람은 옛 모델을 머리에 넣고 그 위에서 판단한다. 2026-09-01 PR #107 리뷰(LOW-3)에서 발견.

**선택지**: (a) 셋을 새 계약에 맞춰 고친다 — 주석만, 코드 0줄. (b) `run.py:84`(거짓 논거)만 고치고 나머지 둘은 불완전 열거로 둔다. (c) 그대로 둔다 — 소비자가 사람뿐이고 `declared_sampling_by_role` docstring이 정본이다.
