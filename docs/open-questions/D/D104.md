## 내용

### 관측 [팀 검수 · 2026-10-03 · 83표본]

harness_final_v1 기반 FT 입력 83표본을 사람이 검수한 결과(원천은 팀 공유 글 · 저장소 밖 · run ID 없음)
- 「필요한 피호출 함수·헬퍼 정의가 없음」 태그 65/83, 그중 18건은 「래퍼까지만 붙고 실제 구현이 없다」로 명시
- 예 -> `buffer_within_range` → `buffer_within_range_` · `ND_TCHECK` → `ND_TCHECK2` · `gf_strdup` → `gf_mem_strdup` · `ThrowImageException` → `ThrowPPException` · `FT_FRAME_EXTRACT` → `FT_Stream_ExtractFrame`
- ImageMagick `AcquireQuantumMemory`처럼 이름 바꾸는 매크로만 붙고 대상 정의를 다시 안 찾는 경우도 있음

### 기제 [코드]

- 피호출 단계(#349 (a), `auditor_callee_hops`)는 **실린 함수의 본문 안 호출**만 정의로 푼다(`GraphIndex.callees_of`). 붙인 피호출 함수의 본문은 다시 안 본다 -> 래퍼가 붙으면 그 안의 실제 구현은 빠짐. `auditor_callee_hops` 상한이 1(「2 이상은 아직 없다」)
- 매크로 정의는 정의 단계(#349 (f))가 붙이는데, 매크로 대치 목록 안의 이름은 다시 안 찾는다. 그리고 매크로 본문 안의 호출은 인덱스 호출 표에 없어 `callees_of`로도 안 닿는다

## 왜 위험한가

- Auditor가 `gf_strdup(s)` 래퍼 한 줄만 보고 할당 크기·길이 검사를 모름 -> 판단 불가로 보류하거나 근거 없이 단정
- FT 데이터가 이 조립기로 만들어짐 -> 학습 입력도 같은 결손

## 선택지

- **(a) 피호출 단계를 무조건 N단으로** -> 입력이 단마다 크게 불어남. 래퍼가 아닌 함수의 피호출까지 다 붙음
- **(b) 래퍼·별칭일 때만 더 따라감** -> 붙인 피호출 함수가 짧고 정의를 아는 함수를 한둘만 부르면 래퍼로 보고 그 함수를 붙임. 실은 매크로가 대치 목록 첫 식별자로 이름만 바꿔 넘기면 그 이름의 정의·함수를 다시 찾음
- **(c) 안 고침** -> 18건 결손이 그대로

## 한계

- 래퍼 판정은 길이·호출 수 근사 -> 짧지만 래퍼가 아닌 함수(검사 하나 + 호출 하나)도 래퍼로 봄. 그 함수의 피호출이 한두 개 더 붙는 정도
- 이름 해석은 `callees_of`와 같은 「같은 파일 아니면 하나뿐일 때만」 규칙 -> 같은 이름 정의가 여럿이면 못 따라감
- 함수 포인터로 넘기는 래퍼(`sys->alloc`)는 이 D 밖 -> 간접 호출(#304 확장 작업)
- 효과는 아직 안 잼 -> 위 18건 표본으로 전후 비교가 남음(이 D는 결함 수정으로 닫고 측정은 FT 데이터 재생성 때 같이 봄)
