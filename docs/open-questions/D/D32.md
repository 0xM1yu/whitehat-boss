# D32 — 컴파일 플래그(-std·-I)가 코드 상수인데 RunRecord에 없다

| 상태 | 관련 문서 |
| --- | --- |
| 부분 | [evaluation.md](../../evaluation.md) §2.3, D29 |

> 인덱스: [docs/open-questions.md](../../open-questions.md) · 작업 추적은 GitHub Issue

## 내용

**2026-08-25 배선 수정에서 표면화됐다.** `_STD_ARGS`(방언)와 `_include_args()`(인클루드 경로) 둘 다 `container_tools.py`의 코드 값이다. `_STD_ARG` 주석이 이미 자기 자신에 대해 적어 뒀다 — "판정 임계값은 아니지만 **분석 결과를 바꾸므로 조건 간 비교에 영향을 준다**". `-I`도 같은 성질이고, 없을 때 20건이 `'zlib.h' file not found`로 죽었으므로 **있고 없고가 신호의 유무를 가른다.** **두 층위를 갈라야 한다.** ① **Evidence 단위(사후 감사) — 보인다**: 모듈 docstring의 규약대로 `_execute`가 `$ {argv}`를 로그 각 절 첫 줄에 쓰고 그 내용이 `Evidence.digest`에 들어간다. "무엇이 실행됐는지"는 검증 가능하다. ② **run 단위(조건 간 비교표) — 안 보인다**: `RunRecord`에 없으므로 두 run을 나란히 놓았을 때 **컴파일 조건이 같았는지 다른지가 표에 나타나지 않는다.** 확인하려면 run마다 Evidence 로그를 열어야 한다. 즉 "안 남겨도 된다"가 아니라 **"사후 감사로는 잡히고 비교표로는 안 잡힌다"**가 정확한 상태다. **`kv_cache_dtype`(모델마다 다른데 `RunRecord`에 없다)·`top_k`(D29)와 같은 종류의 교란변수다** **선택지**: (a) `RunRecord`에 컴파일 조건 필드를 신설 — 스키마 확장은 그 스키마를 읽는 곳이 함께 움직여야 하고 `extra="forbid"` 때문에 뒤처진 쪽이 로드 단계에서 죽는다 (b) `config/budgets.yaml`로 옮긴다 — `_STD_ARG` 주석이 이미 그 방향을 적어 뒀고 `compile_commands.json`이 있는 실저장소에서는 어차피 필요하다 (c) 현행 유지 — **2026-08-25 당시 선택**. **단 무엇을 못 보게 되는지는 이 항목이 들고 있다**. **2026-09-21 — (a)를 구현했다. 부분 해소.** `CompileFlags`(`src/schemas/run.py`)와 `RunRecord.compile_flags`가 생겼고, 값은 **어댑터에게 묻는다** — `ContainerToolRunner.compile_flags()`가 `plan()`이 쓰는 그 상수를 그대로 내고 `factory.Deps`가 러너로 나른다(`tool_images`와 같은 경로. 러너는 `src/adapters/`를 import 할 수 없다). Fake는 **빈 조건**을 내 "컴파일한 도구가 없었다"와 "기록 안 함"을 가른다. **위 (a)가 걱정하던 스키마 확장 비용은 나지 않았다** — `| None = None`이라 `extra="forbid"`에 걸리지 않고 `tests/fixtures/manifests/run_20260817_0004.json`이 그대로 로드된다(그 검사가 fixture 노후화까지 가드한다). ⚠ **닫힘이 아닌 이유는 (b)가 그대로 열려 있기 때문이다** — 값은 **여전히 코드 상수**이고 `_STD_ARGS` 주석의 *"결국 config로 가야 할 값"*은 유효하다. `compile_commands.json`이 있는 실저장소에서는 어차피 필요하다. ⚠ **그리고 기록되는 것은 「고정분」까지다** — `fixed_include_dirs`에 담기는 것은 마운트 루트 하나이고, 대상별 workdir은 명령마다 달라 담지 않는다(담으면 내용이 같은 두 run의 기록이 값만 달라진다). 즉 (a)가 연 것은 **층위 ② 하나**이고 "실제로 어떤 `-I`가 갔나"는 여전히 층위 ①(Evidence 로그의 `$ {argv}`)이 답한다
