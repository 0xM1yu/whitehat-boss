# 취약점 제보 정책과 연구 윤리

## 1. 원칙

1. 발견된 취약점은 **최소 2인 이상의 검증을 거친 후** 제보한다.
2. **AI가 생성한 내용을 그대로 제출하지 않는다.** 사람이 재작성하고 사실을 직접 확인한다.
3. 연구는 **공개된 소스코드와 직접 구축한 로컬 환경**에서만 수행한다. 타인의 운영 시스템을 대상으로 하지 않는다. *(⏵ 2026-09-29 — 「직접 구축한 로컬 환경」은 문자 그대로는 더 이상 사실이 아니다: 모델 서빙이 임대 vast.ai 컨테이너로 옮겼다([D81](open-questions/D/D81.md)). 이 문구를 그대로 둘지 고칠지는 정책 결정이라 이 문서가 정하지 않는다.)*
4. 익스플로잇은 재현 확인에 필요한 최소 수준(PoC/crash 재현)까지만 만든다. 무기화하지 않는다.

## 2. 제보 전 게이트

`proven` 상태의 finding이라도 아래를 모두 통과해야 `reported`로 넘어간다.

### 2.1 기술 검증 (검증자 2인, 서로 독립)

- [ ] 취약 지점의 코드를 **사람이 직접 읽고** 모델 주장과 일치함을 확인
- [ ] source→sink 경로가 실제로 도달 가능함을 확인 (guard, 컴파일 조건, 배포 기본값 포함)
- [ ] 최신 upstream 버전에서도 유효한지 확인 (이미 패치된 것 아닌지)
- [ ] 기존 CVE·이슈·패치와 중복이 아닌지 검색
- [ ] 로컬 환경에서 재현 절차대로 재현 성공
- [ ] 영향 범위(버전, 빌드 옵션, 배포 형태) 명시

### 2.2 문서 검증

- [ ] 제보문에서 AI 생성 문장을 사람이 재작성했는가
- [ ] 모든 기술적 주장에 근거(코드 위치, 로그)가 붙어 있는가
- [ ] 근거 없는 심각도 과장이 없는가
- [ ] 제보처의 보고 양식·정책을 확인했는가

### 2.3 승인 기록

두 검증자의 승인을 구조화해 남긴다. (아래는 합성 예시)

```json
{
  "finding_id": "find_0007",
  "reviewers": ["member_a", "member_b"],
  "review_notes_ref": "artifacts/review/find_0007.md",
  "ai_text_rewritten": true,
  "duplicate_checked": true,
  "approved_at": "2026-10-01T04:00:00Z",
  "target": "upstream project name",
  "channel": "security@ / bug bounty / CNA"
}
```

승인 기록이 없는 제보는 금지한다. 검증자 2인 중 1인은 해당 finding을 생성한 사람이 아니어야 한다.

## 3. 제보 절차

```
proven finding
  → 검증자 2인 배정 (1인은 그 finding을 만들지 않은 사람)
  → 2.1 / 2.2 체크리스트 통과
  → 제보문 작성 (사람이 작성, 근거 첨부)
  → 멘토·PL 최종 확인
  → 제보처 규정에 따라 비공개 채널로 전달
  → 공개 시점은 제보처 정책 준수 (조율 없는 조기 공개 금지)
```

제보처가 응답하지 않는 경우의 처리(대기 기간, 후속 조치)는 제보처 정책을 우선하고, 정책이 없으면 팀에서 결정한다. → [open-questions.md](open-questions.md)

## 4. 발표·공개 시 주의

- 발표와 오픈소스 공개 시 **미패치 취약점의 상세와 PoC는 포함하지 않는다.**
- 발표에는 방법론·지표·비교 결과를 싣고, 개별 취약점은 제보처와 조율된 범위에서만 언급한다.
- 논문·리포트에 실을 코드 예시는 이미 공개된 CVE 또는 합성 예제를 사용한다.

## 5. 금지 사항

- 운영 중인 외부 시스템·서비스에 대한 스캔·익스플로잇 실행
- 제보 전 취약점 상세의 공개 채널 공유(팀 외부 채팅, 소셜 미디어 포함)
- 무기화된 익스플로잇 작성·보관
- 제보처 정책을 어긴 조기 공개
- AI 출력물의 무검증 제출

## 6. 데이터 취급

- 분석 대상 코드는 외부 API로 전송되지 않는다(~~온프레미스 서빙~~). ⏵ **2026-09-29 — 괄호의 근거가 사라졌다.** 모델 호출이 외부 API로 나가지 않는다는 것은 그대로다(`config/models.yaml`의 endpoint가 전부 `127.0.0.1`이거나 `fake://`다). 그러나 서빙은 온프레미스가 아니다: 임대 vast.ai 컨테이너에서 vLLM이 돌므로([D81](open-questions/D/D81.md)) 모델에 보내는 프롬프트에 든 분석 대상 코드가 그 임대 호스트에 닿는다. 아래 「핵심 주장」이 이 전송까지 막겠다는 뜻이었는지, 임대 호스트를 「외부」로 셀지는 정해지지 않았다 — 정책 결정이다. 이는 이 프로젝트의 핵심 주장 중 하나이므로, 외부 전송이 발생하는 경로는 코드 리뷰에서 차단한다.
- 수집한 write-up·CVE 자료는 라이선스와 출처를 L0 메타데이터에 기록한다([knowledge-base.md](knowledge-base.md) §7).
