# 미해결 리스크와 결정 대기 항목

"아직 안 정해짐"을 문서에 숨기지 않기 위한 목록. 결정되면 결론을 해당 문서로 옮기고
여기 행은 상태만 바꿔 남긴다 — 번호를 재사용하지 않기 위해서다(아래 관리 방식).

## 이 목록 관리 방식 (D·R 시리즈 워크플로)

새 결함·결정이 나오면 아래 순서로 다룬다. **이 문서가 진실의 소스이고, GitHub Issue는 그 추적용이다.**

1. **등재**: `docs/open-questions/D/` 아래에 다음 번호로 `Dn.md` 를 만들고, 아래 §2 표에 **한 줄**(번호·항목·상태·본문 링크)을 넣는다. 본문은 파일에만 쓰고 표에는 안 쓴다.
   블로킹 리스크(R)는 `docs/open-questions/R/Rn.md` 와 §1 표로, **같은 형식**이다.
2. **이슈화**: 미해결 **D** 는 GitHub Issue 를 만든다 (제목 `[Dn] 요약`, 라벨 `D-series`). 대기 사유가 있으면 이슈 본문에 적고 열어 둔다.
   **R 은 이슈를 만들지 않는다** — 개별 결함이 아니라 프로젝트 수준 리스크이고, 상태의 원천은 §1 표와 `Rn.md` 다.
3. **수정·닫기**: 고칠 때는 **`Dn.md` 를 먼저** 고치고(해소면 제목에 취소선 + 상태를 `닫힘`으로), **PR 본문에 `Closes #<이슈>`** 를 적어 머지 시 자동으로 닫는다. 일부만 다루면 `Refs #<이슈>`.
4. **머지**: 하네스 팀이 자체 리뷰·머지한다(2026-08-30~).

> **왜 한 항목당 한 파일인가.** 예전에는 표 한 행이 본문 전체(최대 5,500자)를 들고 있었다.
> 그래서 서로 다른 항목을 고치는 두 PR 이 같은 표를 건드렸고, 열을 하나 추가하는 PR 은 55행
> **전부**와 충돌했다(#86 ↔ #87). `docs/decisions/` 가 쓰는 구조로 바꿔 그 원인을 없앴다 —
> 본문 편집은 인덱스를 건드리지 않는다. `tests/test_open_questions_layout.py` 가 강제한다.
> **R 도 2026-09-01에 같은 구조로 옮겼다** — 그때까지 R 은 어떤 검사도 안 받아 1,611자 행(R6)이 있었다.

번호는 **재사용하지 않는다**(해소돼도 번호는 남긴다) — 회의록·PR·이슈가 그 번호로 참조하기 때문. **소각된 번호: D56** — 2026-08-30 커밋 `57f66e1`이 등재 당일 철회하면서 표에서 통째로 지웠다(내용은 PR #56으로 갔다 — 함께 적었던 `experiments/2x2/README.md`는 2026-09-04에 트랙 폐기로 지워졌으므로 지금 남은 소재지는 PR뿐이다). 표의 최대가 D55였을 때 그대로 두면 다음 등재자가 D56을 재사용했을 것이라 D57로 건너뛰었다 — 2026-09-01에 D57이, 2026-09-02에 D58~D62가 등재됐다(등재 없이 열려 있던 이슈 #114·#121·#124·#126·#128을 규약대로 등재). **2026-09-04에 D63·D64·D65가 등재됐다** — 셋 다 이슈보다 등재가 먼저이고, 이슈는 이 등재가 머지된 뒤에 연다(위 1→2단계). **2026-09-09에 D66이 등재됐다**(같은 규약 — 이슈는 머지 뒤). **2026-09-11에 D67**(이슈 #172)**과 D68·D69·D70·D71이 등재됐다** — 뒤 넷은 이슈 #191·#192·#193·#194이고 **#195가 넷을 닫았다**(D68 역할별 차단기·D69 counted_by·D70 unanalyzed_targets·D71 예산 마진). **D72가 등재됐다**(역할별 출력 상한에 위쪽 한계 없음, PR #185·#186). **2026-09-13에 D73이 등재됐다**(D68 (a) 수정의 부수 결과 — 차단기 키 의미. #195 리뷰 MEDIUM-1·2. 이슈는 머지 뒤). **2026-09-14에 D75가 등재됐다**(실험팀 Scout 구조 실측이 확증한 CWE→Agent 목록이 로스터·프롬프트와 다름 — 이슈는 머지 뒤). 직전 번호 하나는 병행 슬라이서·캡슐 PR(#196·#201)이 예약 중이라 이 항목이 D75를 쓴다. **다음 등재는 D76이다.**

## 2. 설계 결정 대기

> **⏸ 모델 선정 대기 보류 (2026-08-30, 5차 회의).** scout·auditor·critic 모델과 오케스트레이션 방안(큰 모델 하나 vs 소형 앙상블)이 확정되기 전까지 그에 종속된 항목은 수정을 보류한다 — 기조가 바뀌면 실측 축이 통째로 달라져 지금 고치는 것이 무의미하다. 해당: **D2·D3·D4·D24·D28**(임계값·양자화·점수·후보수), **D29**(샘플링 등가화 남은 부분), **D51**(열거 강제), **D54**(v2 모델 배선).
>
> **⏵ 2026-09-08 — 여덟 중 여섯이 풀렸다.** 로스터가 제안됐고(ADR 0010 · [09-08 조사](research/2026-09-08-roster.md)) 보류 사유였던 「실측 축이 통째로 달라진다」가 여섯에서 소멸한다 — **D2·D4·D24·D28·D29·D54가 `열림`이다.** 다만 **D2·D4는 질문 자체가 바뀌고**(Scout가 셋으로 쪼개져 임계값이 스칼라가 아니게 되는 것 · Critic 후보가 네이티브 MXFP4라 고정밀 기준선이 없는 것), **D24는 Auditor A/B 둘 다 돌려야** 한다. 각 본문의 2026-09-08 절에 무엇이 바뀌었고 다음 입력이 무엇인지 적었다.
>
> **남은 보류는 둘이고 사유가 서로 다르다.** **D51**은 `trigger_status`를 내는 것이 Auditor라 **A/B 미결이 단독으로 막는 유일한 항목**이다. **D3**은 애초에 보류 사유가 틀렸다 — 모델이 아니라 **`expand()`의 호출부가 저장소에 없어서** `capsule_expansion_max`가 한 번도 안 걸린다(2026-09-08 코드 확인).
>
> **⏵ 2026-09-09 — 로스터가 확정됐다. 그런데 남은 보류 둘은 그대로다.** ADR 0010이 **승인**됐고 [CONTEXT.md](../CONTEXT.md) §1이 로스터의 정본이 됐다 — 바로 위 문단이 근거로 든 「로스터가 **제안**됐고」가 이제 「**확정**됐고」다. **그 승격이 D2·D4·D24·D28·D29·D54의 `열림`을 다시 바꾸지는 않는다** — 그 여섯은 2026-09-08에 이미 풀렸고 각자의 다음 입력도 그때 적혔다. 바뀐 것은 **D24** 하나다: A안·B안이 registry 키로 확정돼(`qwen3-coder-30b-a3b` / `nemotron-3-super-120b-a12b`) 「run 두 번」의 두 대상이 정해졌고, 초안이 Auditor 자리에 적던 제3의 후보(`qwen3.6-35b-a3b`)는 ADR §7로 기각됐다. **대상의 이름이 정해진 것이지 값이 재어진 것은 아니다.**
>
> **⚠ 로스터 확정이 D51을 풀지 않는다.** D51을 막는 것은 로스터가 아니라 **Auditor A/B**인데, ADR 0010 §2가 그 자리를 *"A/B로 남긴다 — 문헌이 정면으로 갈려 실측으로 가른다"*로 **확정하면서 열어 뒀고**, CONTEXT.md §1도 *"Auditor는 A/B다"*로 같은 것을 적는다. 어느 모델의 emit 분포를 보고 `Literal`을 좁힐지가 그대로 미정이라 **보류 유지**다 — 후보가 셋에서 둘로 줄었을 뿐 하나가 아니다. **D3도 그대로다** — 애초에 로스터와 무관한 항목이고(`expand()`의 호출부가 없다) 확정이 그 배선을 만들지 않는다. **보류 표시는 남되 그 사유는 2026-09-08부터 이미 「모델 대기」가 아니다.**
>
> 미해결 D는 GitHub Issue로 추적한다 — **⚠ 2026-09-08 — 이 문장의 「예외 넷」은 낡았다.** D9·D20·D21은 이슈가 있다(#94·#95·#96, 전부 열림 — 2026-09-08 조회). **남은 예외는 D19 하나**이고 그 이슈는 아직 없다.

## 3. 팀·운영 미정

**2026-09-01 — O 계열은 전부 닫혔다.** 트랙(T1~T8) 단위 개발이 폐기되고 하네스를 두 명이
맡기로 정해지면서 O1~O3(트랙 배정·트랙 간 동기화·단계별 역할 분담)은 **전제가 사라졌다.**
O4(평가 데이터셋 6종 TBD)는 데이터셋 확보가 진행 중이고 파인튜닝은 리서치 단계다.
O5(제보처 무응답 대기 기간)와 O7(킥오프 발표 범위)도 함께 닫는다.

> O6(킥오프 PDF 대조)은 그보다 앞선 2026-08-07에 완료됐다. 결과는 D8·D9·O7과 각 문서
> 반영분으로 이관했다.

**행을 남기지 않는다.** D·R 과 달리 O 는 다른 문서·이슈가 번호로 참조하지 않아
번호 재사용 위험이 없고, 본문도 전부 200자 미만이라 파일로 뺄 것이 없었다.

## 4. 기록 규칙

- 항목이 해결되면 결정 내용을 관련 문서에 반영하고, 되돌리기 비싼 결정이면 `docs/decisions/`에 ADR을 남긴다.
- **기한은 두지 않는다.** R과 D를 가르는 것은 날짜가 아니라 성격이다 — R은 프로젝트 수준의
  블로킹 리스크이고 D는 개별 결함·설계 판단이다. 두 계열의 머리 표는 `| 상태 | 관련 문서 |`로 같다.
